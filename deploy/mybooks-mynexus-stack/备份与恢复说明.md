# MyBooks + MyNexus 备份与恢复

部署包 `scripts/` 里的 `backup.sh` + `backup_run.py` 是从原项目移植的全量备份工具，已按新栈改好（容器名 `mybooks`、数据目录 `/volume1/docker/audiobook-data`）。它比手动拷贝可靠：**数据库走 SQLite 官方在线备份 API**（站点运行中也能拿到一致副本），**文件走硬链接快照**（每份都是完整目录树，未变文件共享 inode，增量只占新增空间）。

## 备份内容

- 整个数据目录 `/volume1/docker/audiobook-data`（含书库、`.audio/` 音频、`settings/` 里的**友情链接/AI/MyNexus 全部配置**、数据库），自动排除 `cache/`、`log/`、临时文件
- ★ **MyNexus 的 AI 解析数据也在这棵树里**：`mynexus-data/`（mynexus.db、vectorstore、uploads、logs）与 `mynexus-config/`（config.yaml）。这两个目录由 `.env` 的 `MYNEXUS_DATA_DIR` / `MYNEXUS_CONFIG_DIR` 指定绝对路径，默认就放在数据目录下、**不在 deploy-stack 里**——所以升级时 `deploy-stack` 改名 `.old` 不会丢数据，且会被这里一起备份。
- 数据库单独做一致性快照：`calibre-webserver.db`（用户/阅读记录）、`books/library/metadata.db`（calibre 元数据）

> **老部署补救**：如果之前用的是老版本（MyNexus 数据挂在 `deploy-stack/mynexus-data`、`deploy-stack/mynexus-config`），升级时 `install.sh` 会自动把 `deploy-stack.old/` 里埋住的数据迁到上面的外置目录（幂等、目标非空不覆盖），迁移完就自动纳入本备份。迁移日志形如 `[OK] MyNexus 数据(/data) 已从 .../deploy-stack.old/mynexus-data 迁移到 .../audiobook-data/mynexus-data`。

## 一键备份

在部署目录执行：

```sh
cd /volume1/docker/mybooks-mynexus-stack
sh scripts/backup.sh
```

默认备份到 `/volume1/docker/audiobook-backup/`，保留策略：最近 7 天每天一份 / 最近 4 周每周一份 / 最近 6 个月每月一份。

常用参数：

```sh
sh scripts/backup.sh --dry-run       # 只打印计划，不写文件（首次先跑这个确认）
sh scripts/backup.sh --db-only       # 只备份数据库，秒级，适合高频
sh scripts/backup.sh --files-only    # 只备份书库/音频文件
sh scripts/backup.sh --list          # 查看已有快照及占用空间
```

可用环境变量覆盖默认值，例如：

```sh
BACKUP_ROOT=/volume1/backup KEEP_DAILY=3 sh scripts/backup.sh
```

**定时自动备份**：群晖「控制面板 → 任务计划 → 新增 → 计划的任务 → 用户定义的脚本」，日程设每天凌晨，命令填：

```sh
/bin/sh /volume1/docker/mybooks-mynexus-stack/scripts/backup.sh >> /volume1/docker/audiobook-backup/backup.log 2>&1
```

> 运行器默认 `auto`：本机有 `mybooks:4.7.0-build.09-full` 镜像时走 docker runner（一次性容器只读挂数据目录），否则用本机 python3。两者结果一样。

## 恢复

先看有哪些快照：

```sh
sh scripts/backup.sh --list
```

假设要恢复到某份快照（把 `<时间戳>` 换成实际的，如 `20261120-030000`）：

```sh
# 1. 停容器（恢复数据库前必须停，避免旧进程继续写）
cd /volume1/docker/mybooks-mynexus-stack
docker compose down

# 2. 恢复数据库（从 db/ 快照）
cp -a /volume1/docker/audiobook-backup/db/<时间戳>/webserver.db \
      /volume1/docker/audiobook-data/books/calibre-webserver.db
cp -a /volume1/docker/audiobook-backup/db/<时间戳>/calibre-metadata.db \
      /volume1/docker/audiobook-data/books/library/metadata.db

# 3. 恢复文件/配置（从 files/ 快照，整个数据目录树）
cp -a /volume1/docker/audiobook-backup/files/<时间戳>/. /volume1/docker/audiobook-data/

# 4. 重启
docker compose up -d
```

只需回滚配置（友情链接等）而不动书库时，单独覆盖 `settings/` 即可：

```sh
cp -a /volume1/docker/audiobook-backup/files/<时间戳>/books/settings/. \
      /volume1/docker/audiobook-data/books/settings/
docker compose restart mybooks
```

## 重建搜索索引（可选）

搜索异常（搜不到已知书籍）时重建中文索引。脚本依赖容器内的 webserver 模块，要先拷进容器：

```sh
cd /volume1/docker/mybooks-mynexus-stack
docker cp scripts/search_index.py mybooks:/tmp/search_index.py
docker exec -u 0 mybooks python3 /tmp/search_index.py rebuild
```

重建期间线上搜索继续用旧索引，完成后原子切换，不中断服务。

## 注意

- 恢复数据库前**务必先 `docker compose down`**，否则旧进程继续写库会覆盖恢复结果。
- `backup.sh` 运行时若提示"数据库在线备份失败、回退冷拷贝"，说明容器没在运行——此时数据静止，冷拷贝是安全的。
- 备份目录 `/volume1/docker/audiobook-backup/` 建议放在与数据目录不同的磁盘，避免磁盘故障一起丢。
