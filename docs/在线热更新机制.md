# 在线热更新机制（mode / 白名单 / 重启）

> 本文是「页内立即更新」**能不能生效、点完之后谁负责重启**的唯一权威说明。
> 操作入口和故障处理见 [`在线更新说明.md`](在线更新说明.md)，出包与整包部署见 [`部署包说明.md`](部署包说明.md)。
> 事实来源：`webserver/services/version_check.py`、`scripts/gen-update-manifest.py`（4.6.0-build.27-r29）。

## 1. 判定链：只有四种 mode

`GET /api/admin/version/status` 依次判定（`version_check.py` 的 `status()`）：

| 条件（按顺序命中即返回） | `mode` | 页面表现 |
|---|---|---|
| 远端不比本地新（`revision` 相同或更低、清单不可用） | `none` | 无更新提示 |
| `requires_dist` 为真且 dist 不可热更（`requires_dist and not dist_ok`） | `redeploy` | 只给部署指引，**没有**「立即更新」 |
| 完全没有可投递文件（无 `.py`、无 dist 增删） | `docs_only` | 只提示「有新版本」，无按钮 |
| `base_revision` 与当前修订不一致（跨版本） | `redeploy` | 同上 |
| `hotfixable` 为假 | `redeploy` | 同上 |
| 其余 | `hotfix` | **出现「立即更新」** |

**没有独立的 `dist` 模式**：前端产物和 `.py` 走同一条 `hotfix` 通路，只是投递清单不同。
`can_apply` 只有一个来源：`mode == "hotfix"`。

`dist_ok = latest.dist_hotfixable and bool(dist_files or dist_deleted)`——清单没标 `dist_hotfixable`，
或 dist 数组为空，都算「dist 不可热更」。

## 2. 白名单：只有两类路径允许在线替换

`is_allowed()` 的四组常量：

| 常量 | 值 | 含义 |
|---|---|---|
| `HOTFIX_EXACT` | `{"server.py"}` | 精确匹配 |
| `HOTFIX_PREFIX` | `("webserver/",)` + 必须 `.py` 结尾 | 后端代码 |
| `DIST_PREFIX` | `"app/dist/"` | 前端产物 |
| `DIST_SUFFIX` | `.js .css .html .json .map .txt .png .jpg .jpeg .webp .gif .svg .ico .woff .woff2 .ttf .eot` | 只允许这些后缀 |

另有路径校验：含 `\`、以 `/` 或 `..` 开头、含 `/../` 一律拒绝。

各类文件的实际归属（由 `gen-update-manifest.py` 分类）：

| 路径 | 归类 | 结果 |
|---|---|---|
| `server.py`、`webserver/**/*.py` | `hotfix` | 进 `files[]`，可在线替换 |
| `app/dist/**`（后缀白名单内） | `dist` | 进 `dist_files[]` / `dist_deleted[]` |
| `docs/**`、`*.md` | `docs` | 不进任何数组；页面只会是 `docs_only` |
| `scripts/*.sh` | `docs` | 同上 |
| `tests/**` | `docs` | 同上 |
| `app/src/**` | `appsrc`（blocking） | 顶成 `requires_dist: true` → `redeploy` |
| `app/package.json`、`nuxt.config.js`、`Dockerfile`、`conf/**`、`update/manifest.json` | blocking | 同上 |

**硬塞进 `files[]` 的后果**：apply 在下载、写盘之前逐条校验 `is_allowed`，任何一条不合法就抛
`RuntimeError("发布清单含不允许在线替换的路径：…")`，线上文件一个都不会被改。也就是说
`.md` / 脚本塞进 `files[]` 不会「部分生效」，只会整体失败。

## 3. apply 的执行顺序：先全部校验，再落盘

1. 重新拉远端清单，`revision` 必须等于页面传来的值；
2. 门槛复核：`(requires_dist and not dist_ok) or not hotfixable` 直接拒绝；
3. `base_revision` 必须等于当前本地 `revision`（跨版本不许热更）；
4. 逐条校验路径白名单、`sha256`、`bytes` 字段；`.py` 额外做 `compile()` 语法检查；
5. 全部下载到临时目录，逐个比对大小与 sha256 —— 任何一条失败即中止，**这一阶段线上零改动**；
6. 备份被覆盖的旧文件到 `/data/update-backup/<id>/`（含 `meta.json`：from/to 修订、文件清单、时间），持久化卷，容器重建不丢；
7. 原子替换：写 `CODE_ROOT/<rel>.update-new` 再 `os.replace`；**`index.html` 排最后**；删除 `dist_deleted` 列出项；清掉相关目录的 `__pycache__`；
8. 回写容器内 `CODE_ROOT/update/manifest.json` —— 页面 `current` 从这一刻变新；
9. 复制到 `/data/update-sync/current/`（新清单 + 本次投递的文件）；
10. 写 `/data/update-state.json`（`current_revision` + 最近 10 次 history）。

## 4. 重启是自动的，不需要 `docker restart`

链路：

```
apply 返回 {"restart": True}
  → handler 调 _schedule_restart()
  → call_later(2, sys.exit(0))
  → supervisor（autorestart=true）拉起 python3 server.py
```

**没有任何 in-process reload**（不 `importlib.reload`），机制就是「退出进程 + 监督进程拉起」，
所以新的 `.py` 一定被重新装载。

前端也不是让用户手动刷新：`applyUpdate` 成功后进入轮询，**每 3 秒请求一次 status，最多 30 次（90 秒）**，
服务恢复即 `window.location.reload()`；90 秒未恢复才提示重启失败。另有独立入口
`POST /api/admin/restart`（同样 `sys.exit(0)`），用于不换文件、只重启。

只有当你是**手工替换文件**（`docker cp` / 直接改容器内文件）时才需要自己重启 + 强刷：
手工替换不会走 `apply`，既没有 `sys.exit`，也没有前端轮询，旧 SPA 还在内存里，必须手动刷新。

## 5. dist 门槛：300 文件 / 20 MB，生成清单时判定

`gen-update-manifest.py`：

- `DIST_HOTFIX_MAX_FILES = 300`；
- `DIST_HOTFIX_MAX_BYTES = 20 * 1024 * 1024`（20 MB）。

超限时**整批退回 blocking**：清空 `dist_files` / `dist_deleted`、`dist_hotfixable=false`、
`requires_dist=true` → 页面变 `redeploy`，只能整包部署。

两个细节：

- 字节只累加 `dist_files`（新增与修改），**不算 `dist_deleted`**；删除项数量也不参与门槛；
- 门槛只在**生成清单时**生效。运行时（`status` / `apply`）只读 `dist_hotfixable` 这个布尔值，不再看规模。

## 6. 固化提醒

下次整包 `deploy.sh` / `upgrade.sh` 的第 2 步会调 `sync-hotfix.sh`，把 `/data/update-sync/current`
合并进源码目录再构建。**不要手工跳过这一步**，否则上一次热更的代码会被新镜像冲掉，
表现为「重建后版本号和新功能一起回退」。

## 7. 清单怎么写（一句话口径）

| 本次改动 | `files[]` | `requires_dist` | `hotfixable` | `dist_hotfixable` | 结果 |
|---|---|---|---|---|---|
| 只改 `server.py` / `webserver/**/*.py` | 列改动的 `.py` | `false` | `true` | `false` | 页内「立即更新」，点完自动重启生效 |
| 后端 + 前端，dist ≤ 300 文件且 ≤ 20 MB | `.py` + `dist_files`/`dist_deleted` | `true` | `true` | `true` | 页内「立即更新」，py 与 dist 一起换 |
| 前端超门槛，或改了 blocking 文件（`app/src/**`、`Dockerfile` 等） | 按生成器 | `true` | — | `false` | `redeploy`，只能整包部署 |

以上字段由 `gen-update-manifest.py` 生成，不要手改。
