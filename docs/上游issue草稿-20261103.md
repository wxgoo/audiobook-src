## Issue 1（P0）：Python 3.11 下 `admin.py` / `main.py` 直接 SyntaxError（f-string 内嵌同种引号）

**标题**：`admin.py`、`main.py` 的 f-string 内嵌同种引号，Python ≤ 3.12 以下无法启动

**正文**：

### 现象

用 Python 3.11（及更早）启动时，`webserver/handlers/admin.py` 与 `webserver/main.py`
在 import 阶段就抛 `SyntaxError`，服务无法启动：

```
SyntaxError: f-string: unmatched '('
```

### 原因

两处 f-string 在 `{}` 插值里又用了同种双引号，这是 **PEP 701**（Python 3.12 才允许）：

```python
# webserver/handlers/admin.py（搜 book_type_query，约 L830，v4.6.1）
book_type_query = f"{"not" if book_type == BOOK_TYPE_EBOOK else ""} {CALIBRE_COLUMN_BOOK_TYPE}:={BOOK_TYPE_PHYSICAL}"

# webserver/main.py（搜 The installed version is，约 L436，v4.6.1）
logging.info(f"The installed version is {CONF.get("installed_version", "NONE")}, {"" if is_upgrade else "no"} need to ...")
```

### 复现

```sh
python3.11 -c "import ast; ast.parse(open('webserver/handlers/admin.py').read())"
# SyntaxError: f-string: unmatched '('
```

### 建议修法（先取变量再插值，语义不变）

```python
# admin.py
_not = "" if book_type == BOOK_TYPE_EBOOK else "not"
book_type_query = f"{_not} {CALIBRE_COLUMN_BOOK_TYPE}:={BOOK_TYPE_PHYSICAL}"

# main.py
_installed = CONF.get("installed_version", "NONE")
_need = "" if is_upgrade else "no "
logging.info(f"The installed version is {_installed}, {_need}need to ...")
```

### 说明

- `webserver/` 其余代码没有用到 3.12 特性，只这两处挡住了整个 3.11 兼容
- README 未声明最低 Python 版本；NAS / 自建镜像环境大量是 3.11（Debian 12 系统自带的
  就是 3.11），建议至少修到 3.11 兼容，或在 README 明确 `Requires-Python >= 3.12`
- 该问题在 v4.6.0 已存在，v4.6.1（cdbe366）仍未修，故单独提出来

**标签建议**：`bug`、`python3.11`、`compatibility`

## Issue 2（安全）：播客订阅源接口完全没有权限校验

**标题**：`/podcast/book/<id>` 不校验用户权限，可越权获取任意书籍音频

**正文**：

### 现象

`webserver/handlers/podcast.py` 的 `/podcast/book/<id>` 拿到 `book_id` 后直接生成
整本书音频的订阅源并吐出，**不检查当前用户对该书是否有阅读权限**：

```python
# webserver/handlers/podcast.py（v4.6.1）
def get(self, book_id):
    ...  # 直接查书、出 RSS，没有 visible 检查
```

知道（或遍历）book_id 的任何访客可以绕过阅读范围限制，把受限书籍的整本音频打包下载。

### 建议修法

改动不大，纯加校验：

1. `podcast/podcast_provider.py` 新增 `filter_book_ids(ids, user)`，按既有可见性规则过滤
2. `handlers/podcast.py`：
   - `/podcast/all` 把 `self.current_user` 传下去
   - `/podcast/book/<id>` 先校验，不可见时返回 **404**（而非 403——避免用状态码差异枚举书库）

### 说明

站点即使开启 `REQUIRE_LOGIN`，登录后的普通用户与游客之间仍有阅读范围差异；
此接口目前完全旁路了这套规则。播客功能本身不常用，容易被审计忽略，建议优先处理。

**标签建议**：`bug`、`security`

## Issue 3（依赖）：`app/package.json` 里 nuxt 被 dependabot 升到 4.6.2，与 Vue 2 项目不兼容

**标题**：nuxt 被 dependabot 升到 4.6.2，但项目是 Vue 2 / Nuxt 2，构建链断裂

**正文**：

### 现象

`app/package.json` 中 `nuxt` 已被自动升级为 `^4.6.2`（dependabot 提交），但项目其余
依赖与配置仍是 Vue 2 生态：

- `vue ^2.6.14`、`vuetify ^2.6.10`
- `nuxt.config.js` 为 Nuxt 2 写法

**Nuxt 4 只支持 Vue 3**，这个组合无法工作：

- `npm ci` 表面能过（锁文件未同步更新时）
- `pnpm install` 大概率直接失败；即便装上，`nuxt build` 也会因配置语法不兼容而挂

### 建议修法

`package.json` 回退 `nuxt` 到 `^2.18.x`，并在 dependabot 配置里把 `nuxt` 加入忽略清单
（`package-rules` → `matchPackageNames: ["nuxt"]` → `enabled: false`），直到整体迁移
Vue 3 / Nuxt 3+ 的方案明确为止。

### 说明

这个坑对「照抄上游 package.json 自建镜像」的用户影响最大——构建失败且报错信息
远离真实原因（会被解读成 node 版本或网络问题）。

**标签建议**：`bug`、`dependencies`
