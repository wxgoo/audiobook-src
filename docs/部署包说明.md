## 目录布局（4.6.0-10 起，务必遵守）

```
/volume1/docker/
├── audiobook/                 ← 源码 + 配置，可随意删了重解压
│   ├── Dockerfile
│   ├── docker-compose.yml
│   ├── scripts/
│   │   ├── upgrade.sh        ← 升级入口
│   │   ├── deploy.sh         ← 首次装机
│   │   ├── check-reader.sh   ← 排障（只读）
│   │   ├── protect-custom.sh
│   │   ├── upgrade-upstream.sh
│   └── （归档脚本不打包，只在源码仓库里）
│   └── app/ webserver/ conf/ ...
│
└── audiobook-data/            ← ★ 唯一数据目录，永不被升级流程触碰 ★
    ├── books/
    │   ├── calibre-webserver.db    ← 用户/权限/设置数据库
    │   ├── library/                ← 书库 + metadata.db
    │   │   └── <作者>/<书名> (id)/  ← 一本书一个目录
    │   │       ├── xxx.epub
    │   │       └── .audio/         ← 这本书的有声书音频（4.6.0-13 起）
    │   ├── audios/                 ← 旧布局音频，迁移后应为空
    │   ├── upload/ imports/ settings/ progress/ ...
    ├── cache/
    ├── log/
    ├── reader/
    ├── sync/
    └── toolbox/
```

**核心原则：源码目录里绝不能出现 `books/`、`data/`、`library/`、`audios/` 这类目录。**

`docker-compose.yml` 里写死了 `- /volume1/docker/audiobook-data:/data`，
程序内部所有路径都是容器内 `/data/books/...`，所以宿主机上数据只存在于 `audiobook-data/`。

`scripts/deploy.sh` 和 `scripts/upgrade.sh` 都会在开头做污染自检，发现源码目录里有数据类目录会直接停止并提示。

## 首次安装

```bash
cd /volume1/docker
mkdir -p audiobook
tar -xzf audiobook-deploy-4.6.0-19-r13-patched.tar.gz -C audiobook --strip-components=1
mkdir -p audiobook-data          # 数据目录必须先存在
cd audiobook
sh scripts/deploy.sh
```

> `--strip-components=1` 用于去掉包内的 `audiobook-deploy-4.6.0-14/` 外层目录。
> 若包结构第一层直接是 `app/ webserver/ Dockerfile`，则不加该参数。
> 用 `tar -tzf 包名 | head -3` 先看一眼即可判断。

`scripts/deploy.sh` 依次做：**源码目录污染自检** → 关键文件校验 → MyReader 产物完整性（有效链接数、三层 node_modules）
→ `docker compose build` → `docker compose up -d` → 启动验证。
只构建不启动：`sh scripts/deploy.sh build-only`。

## 升级 / 重装（推荐用 scripts/upgrade.sh）

> ⚠️ **不要**直接在 `audiobook/` 里 `tar -xzf` 新包——旧文件残留会和新包叠加，
> 这正是"源码目录变脏"的根源。

正确做法：

```bash
cd /volume1/docker
sh audiobook/scripts/upgrade.sh /volume1/docker/audiobook-deploy-4.6.0-19-r13-patched.tar.gz
```

`scripts/upgrade.sh` 的执行顺序（每步都有保护）：

| 步骤 | 动作 | 保护点 |
|---|---|---|
| 0 | 预检压缩包结构 | 包内若含 `books/library` 等数据目录会警告并要求确认 |
| 1 | 检查 `audiobook-data/books` 存在 | 不存在则停止，防止数据目录被误建为空 |
| 2 | 备份 `*.db` 到 `audiobook-data-dbbackup-时间戳/` | 只备份数据库，秒级；`NO_BACKUP=1` 可跳过 |
| 3 | `docker compose down` | 消除写入中的风险 |
| 4 | 旧源码 `mv audiobook → audiobook.old` | 不删除，保留回滚可能 |
| 5 | `mkdir audiobook` 后全新解压 | **全新目录，绝不叠加** |
| 6 | 污染自检 + 挂载校验 | 有数据类目录则停止；compose 未指向 `audiobook-data` 则停止 |
| 7 | `docker compose build` | `SKIP_BUILD=1` 可跳过 |
| 8 | 启动 + 校验书数 + 清理 `.old` | 打印书数供对比；`KEEP_OLD=1` 保留旧源码 |

可选环境变量：

```bash
SKIP_BUILD=1 sh scripts/upgrade.sh 包.tar.gz   # 只解压看代码，不构建
SKIP_UP=1    sh scripts/upgrade.sh 包.tar.gz   # 解压+构建，不启动
KEEP_OLD=1   sh scripts/upgrade.sh 包.tar.gz   # 保留 audiobook.old
NO_BACKUP=1  sh scripts/upgrade.sh 包.tar.gz   # 不备份数据库（不推荐）
```

升级后验证：

```bash
docker exec -it audiobook-mybooks-1 supervisorctl status
# 四个进程均应为 RUNNING（myreader 不能是 FATAL/BACKOFF）
```

## 手动升级（等效于脚本，便于理解或排查）

```bash
cd /volume1/docker

# 1. 停服务
docker compose -f audiobook/docker-compose.yml down

# 2. 旧源码改名（不删）
mv audiobook audiobook.old

# 3. 全新目录解压
mkdir audiobook
tar -xzf audiobook-deploy-4.6.0-19-r13-patched.tar.gz -C audiobook --strip-components=1

# 4. 污染自检（应无输出）
ls -d audiobook/books audiobook/book audiobook/data audiobook/library 2>/dev/null

# 5. 确认数据挂载正确
grep ":/data" audiobook/docker-compose.yml
# 期望输出: - /volume1/docker/audiobook-data:/data

# 6. 构建启动
cd audiobook && docker compose build && docker compose up -d
sleep 25 && docker exec audiobook-mybooks-1 supervisorctl status

# 7. 确认无误后清掉旧源码
cd /volume1/docker && rm -rf audiobook.old
```

**记住一句话：先 `mv` 走旧的，再 `mkdir` 全新的，永远不叠加。**

## 如果源码目录已经被污染

症状：`ls audiobook/` 看到 `books/`、`data/`、`library/`、`audios/` 等。

```bash
cd /volume1/docker

# 1. 先停容器
docker compose -f audiobook/docker-compose.yml down

# 2. 确认这些目录里有什么（不要急删）
du -sh audiobook/books audiobook/data 2>/dev/null

# 3. 如果里面的数据比 audiobook-data 里的新/全，先搬过去
#    （同盘 mv 是 rename，秒级，不占双倍空间）
mkdir -p audiobook-data
[ -d audiobook/books ] && mv audiobook/books/* audiobook-data/books/ && rmdir audiobook/books

# 4. 确认数据完整
ls audiobook-data/books/        # library/ audios/ calibre-webserver.db 都要在

# 5. 起容器验证书数
docker compose -f audiobook/docker-compose.yml up -d && sleep 25
docker exec audiobook-mybooks-1 python3 -c \
  "import sqlite3;print('书数:',sqlite3.connect('/data/books/library/metadata.db').execute('select count(*) from books').fetchone()[0])"

# 6. 一切正常后，跑 scripts/upgrade.sh 重装一次源码，得到干净的目录
sh audiobook/scripts/upgrade.sh /volume1/docker/audiobook-deploy-4.6.0-19-r13-patched.tar.gz
```

## 日常运维

```bash
# 读者组分类回填（先 dry-run 预览，确认后加 --apply）
docker exec -it audiobook-mybooks-1 python3 /var/www/mybooks/tools/category_backfill.py
docker exec -it audiobook-mybooks-1 python3 /var/www/mybooks/tools/category_backfill.py --apply

# MyReader 状态 / 日志
# ⚠ supervisor 程序名必须带组前缀（mybooks:xxx），写 myreader 会报 no such process
docker exec -it audiobook-mybooks-1 supervisorctl status mybooks:myreader
docker exec -it audiobook-mybooks-1 tail -50 /data/log/myreader.log
```

### 只改前端的临时热更（不重启服务）

`dist/_nuxt/*.js` 由 nginx 直接发，替换文件后浏览器 **Ctrl+Shift+R** 即可，**不用 restart**。

```bash
# 1) 上传新包到 NAS 后，在 /volume1/docker 下解（路径别少）
cd /volume1/docker && tar xzf audiobook-deploy-4.6.0-19-r13-patched.tar.gz

# 2) dist 用 tar 管道拷进容器
#    ⚠ 不能用 docker cp src/. 目标/：镜像里 dist/avatar 是文件、宿主是目录，会报
#      "cannot overwrite non-directory ... with directory"
tar c -C /volume1/docker/audiobook/app dist | docker exec -i audiobook-mybooks-1 tar x -C /var/www/mybooks/app
```

改后端 Python 才需要重启，且必须带组前缀：

```bash
docker exec -it audiobook-mybooks-1 supervisorctl restart mybooks:tornado
docker exec -it audiobook-mybooks-1 supervisorctl status   # 确认 4 个进程全 RUNNING
```

**只需备份 `audiobook-data/` 一个目录**，源码随时可从包或 Gitee 重取。

```bash
# 完整备份（含书和音频，体积大）
tar -czf /volume1/docker/audiobook-data-$(date +%F).tar.gz \
  -C /volume1/docker audiobook-data

```

## 命名说明

对外目录/包名统一叫 `audiobook`（与 NAS 上的 `/volume1/docker/audiobook`、
容器名 `audiobook-mybooks-1` 一致）。代码内部运行路径 `/var/www/mybooks`、
`/var/www/myreader` 是上游程序写死的，不影响使用，请勿修改。
