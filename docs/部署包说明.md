## 目录布局（4.6.0-10 起，务必遵守）

```
/volume1/docker/
├── audiobook/                 ← 源码 + 配置，可随意删了重解压
│   ├── Dockerfile
│   ├── docker-compose.yml
│   ├── scripts/
│   │   ├── upgrade.sh        ← 升级入口
│   │   ├── deploy.sh         ← 首次装机
│   │   ├── check-reader.sh   ← 排障（只读）
│   │   ├── hotfix.sh         ← 只改 Python 时用（省镜像重建）
│   │   ├── protect-custom.sh
│   │   ├── upgrade-upstream.sh
│   │   ├── watch-upstream.py  ← 盯上游
│   │   └── migrate-audio-dirs.py / test-*.py / test-integration.sh
│   └── （归档脚本不打包，只在源码仓库里）
│   └── app/ webserver/ conf/ ...
│
└── audiobook-data/            ← ★ 唯一数据目录，永不被升级流程触碰 ★
    ├── books/
    │   ├── calibre-webserver.db    ← 用户/权限/设置数据库
    │   ├── library/                ← 书库 + metadata.db
    │   │   └── <作者>/<书名> (id)/  ← 一本书一个目录
    │   │       ├── xxx.epub
    │   │       └── .audio/         ← 这本书的有声书音频（4.6.0-13 起）
    │   ├── audios/                 ← 旧布局音频，迁移后应为空
    │   ├── upload/ imports/ settings/ progress/ ...
    ├── cache/
    ├── log/
    ├── reader/
    ├── sync/
    └── toolbox/
```

**核心原则：源码目录里绝不能出现 `books/`、`data/`、`library/`、`audios/` 这类目录。**

`docker-compose.yml` 里写死了 `- /volume1/docker/audiobook-data:/data`，
程序内部所有路径都是容器内 `/data/books/...`，所以宿主机上数据只存在于 `audiobook-data/`。

`scripts/deploy.sh` 和 `scripts/upgrade.sh` 都会在开头做污染自检，发现源码目录里有数据类目录会直接停止并提示。

## 首次安装

```bash
cd /volume1/docker
mkdir -p audiobook-data          # 数据目录必须先存在

# 包内第一层就是 audiobook/，直接解到 /volume1/docker 即可，不要 --strip-components
tar -xzf audiobook-deploy-4.6.0-build.26.tar.gz -C /volume1/docker

cd audiobook
sh scripts/deploy.sh
```

> **修正（本包）**：旧文档这里写的是 `tar -xzf ... -C audiobook --strip-components=1`
> 与历史包名，那是「包内还有一层同名目录」时的写法。本包顶层已经是 `audiobook/`，
> 再 `--strip-components=1` 会把 `Dockerfile`、`app/` 等直接铺到 `/volume1/docker`，
> 目录结构就错了。先用 `tar -tzf 包名 | head -3` 确认第一层是 `audiobook/...`。

`scripts/deploy.sh` 依次做：**源码目录污染自检** → 关键文件校验 → MyReader 产物完整性（有效链接数、三层 node_modules）
→ `DOCKER_BUILDKIT=0 docker build --no-cache -t mybooks-local:latest .` → 镜像内
`dist/index.html` 与包内逐字节比对 → `docker compose up -d --force-recreate --no-build` → 启动验证。
只构建不启动：`sh scripts/deploy.sh build-only`。

## 升级 / 重装（推荐用 scripts/upgrade.sh）

> ⚠️ **不要**直接在 `audiobook/` 里 `tar -xzf` 新包——旧文件残留会和新包叠加，
> 这正是"源码目录变脏"的根源。

正确做法：

```bash
cd /volume1/docker
sh audiobook/scripts/upgrade.sh /volume1/docker/audiobook-deploy-4.6.0-build.26.tar.gz
```

> 不想用脚本时的**唯一正确路径**（等价于 upgrade.sh，也是本文档推荐口径）：
> 停容器 → 旧目录改名 `audiobook.bak-时间戳` → 全新解压到 `audiobook/` →
> `DOCKER_BUILDKIT=0 docker build --no-cache -t mybooks-local:latest .` →
> `docker compose up -d --force-recreate --no-build`。
> **不要**在旧目录上直接解压叠加，更**不要**用 `docker cp` 或 tar 管道只补部分文件——
> 那会造成「入口 index.html 旧、`_nuxt` 新」的半新半旧状态（上一轮就是这样出的问题）。

`scripts/upgrade.sh` 的执行顺序（每步都有保护）：

| 步骤 | 动作 | 保护点 |
|---|---|---|
| 0 | 预检压缩包结构 | 包内若含 `books/library` 等数据目录会警告并要求确认 |
| 1 | 检查 `audiobook-data/books` 存在 | 不存在则停止，防止数据目录被误建为空 |
| 2 | 备份 `*.db` 到 `audiobook-data-dbbackup-时间戳/` | 只备份数据库，秒级；`NO_BACKUP=1` 可跳过 |
| 3 | `docker compose down` | 消除写入中的风险 |
| 4 | 旧源码 `mv audiobook → audiobook.old` | 不删除，保留回滚可能 |
| 5 | `mkdir audiobook` 后全新解压 | **全新目录，绝不叠加** |
| 6 | 污染自检 + 挂载校验 | 有数据类目录则停止；compose 未指向 `audiobook-data` 则停止 |
| 7 | `DOCKER_BUILDKIT=0 docker build --no-cache -t mybooks-local:latest .`（构建后自动比对镜像内 `dist/index.html`） | `SKIP_BUILD=1` 可跳过 |
| 8 | 启动 + 校验书数 + 清理 `.old` | 打印书数供对比；`KEEP_OLD=1` 保留旧源码 |

可选环境变量：

```bash
SKIP_BUILD=1 sh scripts/upgrade.sh 包.tar.gz   # 只解压看代码，不构建
SKIP_UP=1    sh scripts/upgrade.sh 包.tar.gz   # 解压+构建，不启动
KEEP_OLD=1   sh scripts/upgrade.sh 包.tar.gz   # 保留 audiobook.old
NO_BACKUP=1  sh scripts/upgrade.sh 包.tar.gz   # 不备份数据库（不推荐）
```

升级后验证：

```bash
docker exec -it audiobook-mybooks-1 supervisorctl status
# 四个进程均应为 RUNNING（myreader 不能是 FATAL/BACKOFF）
```

## 手动升级（等效于脚本，便于理解或排查）

```bash
cd /volume1/docker

# 1. 停服务
docker compose -f audiobook/docker-compose.yml down

# 2. 旧源码改名（不删）
mv audiobook audiobook.bak-$(date +%Y%m%d-%H%M%S)

# 3. 全新目录解压（包内第一层就是 audiobook/，不要 --strip-components）
tar -xzf audiobook-deploy-4.6.0-build.26.tar.gz -C /volume1/docker

# 4. 污染自检（应无输出）
ls -d audiobook/books audiobook/book audiobook/data audiobook/library 2>/dev/null

# 5. 确认数据挂载正确
grep ":/data" audiobook/docker-compose.yml
# 期望输出: - /volume1/docker/audiobook-data:/data

# 6. 构建启动（dist 已在包内，NAS 不构建前端）
cd audiobook
DOCKER_BUILDKIT=0 docker build --no-cache -t mybooks-local:latest .
# 构建后必验：镜像内 index 必须与包内一致（本包期望 f8771fea…）
docker run --rm mybooks-local:latest sha256sum /var/www/mybooks/app/dist/index.html
docker compose up -d --force-recreate --no-build
sleep 25 && docker exec audiobook-mybooks-1 supervisorctl status

# 7. 确认无误后清掉旧源码（保留最新一份备份即可）
cd /volume1/docker && rm -rf audiobook.bak-*
```

**记住一句话：先 `mv` 走旧的，再 `mkdir` 全新的，永远不叠加。**

## 如果源码目录已经被污染

症状：`ls audiobook/` 看到 `books/`、`data/`、`library/`、`audios/` 等。

```bash
cd /volume1/docker

# 1. 先停容器
docker compose -f audiobook/docker-compose.yml down

# 2. 确认这些目录里有什么（不要急删）
du -sh audiobook/books audiobook/data 2>/dev/null

# 3. 如果里面的数据比 audiobook-data 里的新/全，先搬过去
#    （同盘 mv 是 rename，秒级，不占双倍空间）
mkdir -p audiobook-data
[ -d audiobook/books ] && mv audiobook/books/* audiobook-data/books/ && rmdir audiobook/books

# 4. 确认数据完整
ls audiobook-data/books/        # library/ audios/ calibre-webserver.db 都要在

# 5. 起容器验证书数
docker compose -f audiobook/docker-compose.yml up -d && sleep 25
docker exec audiobook-mybooks-1 python3 -c \
  "import sqlite3;print('书数:',sqlite3.connect('/data/books/library/metadata.db').execute('select count(*) from books').fetchone()[0])"

# 6. 一切正常后，跑 scripts/upgrade.sh 重装一次源码，得到干净的目录
sh audiobook/scripts/upgrade.sh /volume1/docker/audiobook-deploy-4.6.0-19-r13-patched.tar.gz
```

### 包内容裁剪（有意排除，不是漏打）

### 前端已在包内预构建，禁止「只补部分文件」

> **本节为修正内容。** 旧文档曾给出「把 `dist` 用 tar 管道 / `docker cp` 拷进容器」的
> 热更做法，上一轮正是这样造成了「容器内 `index.html` 还是旧 chunk、同目录 `_nuxt` 已是

```bash

  三件齐备就跳过前端构建）。
- **为什么必须 `--no-cache`**：本机没有 buildx 插件，回落到 legacy builder；legacy 的
  `COPY` 缓存按内容 checksum 判重，但缓存链里可能残留上一代 `app/dist` 的层。
  `--no-cache` 让所有步骤重跑，彻底绕开旧层。
- **为什么不能用 `docker compose build`**：compose v2 自带 buildx 库，其上下文快照按
  `mtime + size` 判重。旧包把 `index.html` 的 mtime 固定成常量、体积又同为 4901 字节，

  `dist/` 整体来自同一份包，不会再出现入口与资源不同源（Dockerfile 内有两道硬校验，

## 常见构建失败（build.26 收录，均为 build.25 现场实录）

### 1. `failed to export image: … layer does not exist`

出现在构建日志 **Step 11 `COPY app/` 之后**（前面 69 步全绿，最后导出镜像时炸）。
根因是 btrfs 存储驱动下层索引被写坏：现场当时有 88 个悬空镜像、56.79GB 占用、
1595 条 BuildKit 缓存，而机器只有 2GB 内存；**并发跑两个 build 会互删中间层**。

处理顺序（**别搞反，先 prune 等于逼自己全量重建**）：

```bash
# 1) 先重启守护进程，重建层索引（最有效的一步）
synopkg restart ContainerManager

# 2) 再构建，且不要带 --no-cache —— 复用仍在的缓存层，正好绕开写坏的那层
DOCKER_BUILDKIT=0 docker build --build-arg GIT_VERSION=<包内版本> -t mybooks-local:latest .

# 3) 仍失败：清碎片后全量重建
docker image prune -f          # 只删无标签悬空层，约 50GB
docker builder prune -af       # 只删构建缓存
synopkg restart ContainerManager
DOCKER_BUILDKIT=0 docker build --no-cache --build-arg GIT_VERSION=<包内版本> -t mybooks-local:latest .

# 4) 仍失败：换 BuildKit 这条路过一次
DOCKER_BUILDKIT=1 docker build --build-arg GIT_VERSION=<包内版本> -t mybooks-local:latest .
```

第 1～3 步已固化成脚本：**`sh scripts/recover.sh build`**（只到构建+校验，不动容器）、
`sh scripts/recover.sh`（一路到起容器+全链路校验）、`sh scripts/recover.sh check`（只体检不改动）。
`scripts/fix-build-layer.sh` 是七步只读诊断，怀疑层坏了先跑它。

> `image prune -f` 与 `builder prune -af` 都**不会**删带标签的镜像、也不碰数据卷；
> 不要用 `docker system prune -a`，那会连 `node:20-alpine`、`poxenstudio/mybooks_base` 一起删掉。

### 2. 重启 Docker 的正确口径（DSM 7.2）

| 你以为 | 实际 |
|---|---|
| `synoservice --restart pkgctl-Docker` | `synoservice: command not found`（DSM 7.1+ 已移除） |
| `systemctl restart docker` | `Unit docker.service failed to load`（不受 systemd 管理） |
| 套件名 `Docker` | DSM 7.2 起叫 **`ContainerManager`** |

正确写法：`synopkg restart ContainerManager`（完整路径 `/usr/syno/bin/synopkg`），
或套件中心 → Container Manager → 停止 / 启动。`ls /var/packages | grep -i container`
可以先确认套件真名。重启后要等到 `docker info` 有响应再动手（`recover.sh` 会等最多 180 秒）。

### 3. `docker compose up` 误拉镜像 → 站点直接中断

现场出网被中间人改写，任何 pull 必失败（`x509: certificate is not valid for any names`）。
`docker compose up -d --force-recreate` 会**先删容器再拉镜像**，镜像拉不到 → 容器没了、站点打不开。

```bash
# 镜像已在本地时，务必锁死「不构建、不拉取」
docker compose up -d --force-recreate --no-build --pull never

# 还不行就绕开 compose，纯 docker 起（不触碰 registry）
docker rm -f audiobook-mybooks-1
docker run -d --name audiobook-mybooks-1 --restart always -p 9800:80 \
  -v /volume1/docker/audiobook-data:/data \
  --security-opt seccomp=unconfined mybooks-local:latest
```

预防：**升级只用 `scripts/upgrade.sh`**（内部一律 `--no-build`），不要手工 `compose up`。
