## 3. 方式 A：git am（保留提交历史，推荐）

```sh
cd <源码目录>
git checkout -b opt-apply 32bc1d4

# 全部应用
git -c core.autocrlf=false am delivery/patches/*.patch

# 校验
git rev-parse 'HEAD^{tree}'   # 期望 f2a9b5ad736267c5a92824fd70c584aed2d3582c
```

若只想应用其中几项，直接指定文件即可（例如只上安全和音频）：

```sh
git am delivery/patches/02-P1-1-mcp-token.patch \
       delivery/patches/03-P1-2-ws-origin.patch \
       delivery/patches/05-P1-4-audio-range.patch
```

### 冲突处理

- 优先 `git am -3 delivery/patches/0X-*.patch`（基线 blob 存在时可三方合并）。
- 冲突后：`git status` 看冲突文件 → 手工改 → `git add <file>` → `git am --continue`。
- 放弃本次：`git am --abort`；跳过这一条（例如上游已修）：`git am --skip`。
- 上游 mybooks 4.6.0 与本 fork 差异较大，**A/B/C/D 主题补丁在应用到上游时大概率冲突**，
  这是预期行为；按 `docs/上游跟进/*.md` 的「补丁要点」手工取舍，不要整包硬套。

## 4. 方式 B：git apply（不生成提交）

```sh
git apply --check delivery/all-in-one.patch     # 只检查
git apply --stat  delivery/all-in-one.patch     # 看改动面
git apply delivery/all-in-one.patch             # 应用到工作区
```

合集补丁不含提交信息，适合「先看效果再决定是否提交」。
若个别文件失败：`git apply --3way --reject delivery/all-in-one.patch`，
失败片段会写成 `*.rej`，逐个处理后删除。

## 6. 逐项回滚

三种方式，按场景选：

```sh
# 1) 已按方式 A 应用并保留了提交：按提交回滚（最安全）
git revert <对应提交短哈希>          # 单条
git revert --no-commit <h1> <h2> && git commit   # 多条合并成一次

# 2) 无提交历史（方式 B）：反向应用补丁
git apply -R delivery/patches/05-P1-4-audio-range.patch

# 3) 整包回滚到基线（确认无本地改动后）
git checkout 32bc1d4 -- .            # 仅回滚工作区文件，历史保留
```

补丁与提交对照见 `docs/archive/优化实施与决策记录.md` 的提交表；`01`–`14` 顺序与提交顺序一致。

**回滚注意**

- `04/06` 回滚后可把 `AUDIO_CACHE_REFRESH_SECONDS` 调回 `300` 以恢复旧频率。
- `07` 回滚只需 `SEARCH_INDEX_ENABLED=False`，不必回滚代码。
- `08` 回滚只要前端不再传 `after` 参数，旧 `start/size` 即恢复。
- `02` 回滚后旧客户端可在 URL 带 token，但请尽快迁回 Header。
- 备份 `01` 回滚只需停 cron，不影响业务代码与已有快照。
