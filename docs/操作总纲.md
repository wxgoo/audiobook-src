> 最后更新：4.6.0-15（基于上游 mybooks tag `4.6.0`）

## ⚠️ 零、两个操作环境，别搞混

本手册里所有命令分属两个地方，**跑错位置会报 `no such file or directory`**：

| 环境 | 在哪 | 有什么 | 干什么 |
|---|---|---|---|
| **开发侧**（沙箱 / 你的 Windows） | 见下方"开发侧怎么去" | git 仓库、完整源码 | 改代码、git 提交、推 Gitee、打补丁包 |
| **NAS**（群晖 RS2416P） | `/volume1/docker/` | 现役源码、数据、部署包 | 收包、合并出成品包、upgrade.sh 上线 |

- 文中标注 **【开发侧】** 的步骤 → 在开发侧做，**NAS 上执行会失败**
- 文中标注 **【NAS】** 的步骤 → SSH 登录群晖做
- 例外：`upgrade-upstream.sh` 虽然在 NAS 上跑，但它会自己在 `/tmp` 里临时 clone 仓库，所以不需要 NAS 预装 git 仓库

### 开发侧怎么去？三种方式，按省事程度排

#### 方式 1：直接对 AI 说（推荐，零门槛）

在对话框里说"把 XX 改成 YY"，AI 在沙箱里改代码 → 提交 → 推 Gitee → 打补丁包 → 给你下载链接。
**你只需下载包、传 NAS、跑 upgrade.sh，全程不碰命令行。**

适合：99% 的情况。

#### 方式 2：Gitee 网页直接改（适合改文案、小改动）

1. 浏览器打开 https://gitee.com/wxgoo/audiobook-src
2. 定位到文件（如 `app/locales/zh.json`）
3. 点右上角**编辑**（铅笔图标），改完点"提交"到 master
4. 出包仍需回到方式 1（让 AI 帮你打补丁包）

适合：改几个字、改提示语。

#### 方式 3：Windows 装 Git（想自己长期独立维护才用）

```sh
# 1. 装 Git for Windows：https://git-scm.com/download/win
# 2. 克隆到本地
git clone https://gitee.com/wxgoo/audiobook-src.git D:\audiobook-src
# 3. 用 VS Code 打开 D:\audiobook-src 改代码（有语法高亮、能搜整个项目）
# 4. 提交推送
cd D:\audiobook-src
git add -A
git commit -m "改了什么"
git push https://wxgoo:<令牌>@gitee.com/wxgoo/audiobook-src.git master
```

适合：想自己改核心逻辑、需要改很多文件、要本地跑测试。

## 一、先认清 5 样东西

| 名字 | 位置 | 是什么 | 能不能删 |
|---|---|---|---|
| **audiobook** | `/volume1/docker/audiobook/` | 正在运行的源码（容器从这里启动） | ❌ 不能删 |
| **audiobook-data** | `/volume1/docker/audiobook-data/` | **所有数据和书**（11GB，唯一数据目录） | ❌ 绝对不能删 |
| **成品部署包** | `/volume1/docker/audiobook-deploy-<版本>.tar.gz` | 约 250M 完整代码包，用来升级/重装 | 留最近两三版，更老的删掉 |
| **Gitee 仓库** | gitee.com/wxgoo/audiobook-src（master） | 代码备份 + 版本历史 | — |

**一句话铁律**：数据和源码永远分开。`audiobook/` 里一旦出现 `books/`、`data/`、`audios/` 目录，就是出错了。

## 三、跟随上游升级（4.6.0 → 新版本）

### 最省事的方式：一条命令（在 NAS 上执行）

```sh
sh /volume1/docker/audiobook/scripts/upgrade-upstream.sh
```

> 这个脚本把"开发侧"和"NAS"两边的活全包了：它在 `/tmp/up-upgrade/` 里临时 clone 仓库、合并上游、
> 出包并上线，全程不碰你 NAS 上现役的 `audiobook/` 目录（直到最后 upgrade.sh）。
> 唯一前提：**NAS 能访问 GitHub**（要 fetch 上游）。访问不了就在开发侧做，见下方"手动方式"。

脚本会依次问你/自动做：

| 步骤 | 脚本做什么 | 你要做什么 |
|---|---|---|
| 1 | 拉取 Gitee 上的代码 | 等着 |
| 2 | 查询上游最新版本号 | 等着（或手动输入，如 `4.7.0`） |
| 3 | 合并上游代码 | **可能有冲突**，见下方 |
| 3.1 | 合并前给 `BOOK_NAV` 和三语文案拍快照 | 等着 |
| 3.2 | 合并后回灌 + 校验自定义内容 | 若有改动会列出来，你确认后回车 |
| 4 | 检查代码完整性（含自定义内容再校验一次） | 暂停 → 你测试确认后回车 |
| 5 | 推送 Gitee | 等着 |
| 6 | 出成品包 `audiobook-deploy-4.7.0-1.tar.gz` | 等着 |
| 7 | 执行 upgrade.sh 上线 | 等着，最后验证网页 |

> **3.1 / 3.2 是干什么的**：`webserver/settings.py` 里的 `BOOK_NAV`（默认分类导航，上游 9 组、我们 13 组）
> 和 `app/locales/*.json` 三语文案，是上游升级时**必然被整段覆盖**的两处。
> 覆盖后不报错、不崩，只是分类导航悄悄变回上游版、界面开始显示 `settings.xxx` 这种原始键名——
> 最难发现的那种坏法。所以合并前自动存快照，合并后自动补回去并校验。
>
> 这套逻辑在 `scripts/protect-custom.sh`，也可以单独用：
>
> ```sh
> sh scripts/protect-custom.sh save  <源码目录>   # 存快照
> sh scripts/protect-custom.sh apply <源码目录>   # 回灌
> sh scripts/protect-custom.sh check <源码目录>   # 校验（缺什么报什么，不通过返回 1）
> ```
>
> 注意：`upgrade-upstream.sh` 与 `protect-custom.sh` 必须放在**同一层目录**（仓库里都在 `scripts/`）。
> 脚本会依次在「自己所在目录 → 上一层 `scripts/` → `/volume1/docker/scripts/` → `/volume1/docker/`」找，
> 都没有就提示"找不到 protect-custom.sh"，校验被跳过。

### 第 3 步遇到冲突怎么办

脚本会停下来，列出冲突文件（通常就 2~3 个）。处理规矩：

| 冲突文件 | 怎么办 |
|---|---|
| `webserver/settings.py` | 保留你的 `/data` 路径，同时把上游新增的配置项抄进来 |
| `docker-compose.yml` | 保留你的挂载写法 `/volume1/docker/audiobook-data:/data` |
| `myreader-dist` 目录 | 一律要自己的：`git checkout --ours myreader-dist && git add myreader-dist` |
| 其他文件 | 一般保留上游新版，删掉 `<<<<<<<` `=======` `>>>>>>>` 这些标记行 |

改完后：

```sh
cd /tmp/up-upgrade/audiobook
git add -A
git commit
```

**然后重新运行同一条命令**，脚本会自动从断点继续。

### 手动方式【开发侧】（NAS 访问不了 GitHub 时用）

```sh
# 1. 在开发机/沙箱上
cd /root/work/audiobook-src
git fetch upstream --tags
git tag 4.6.0-before-upgrade          # 存档，可回退
git merge 4.7.0                       # 上游 tag 无 v 前缀

# 2. 有冲突就按上表处理，然后
git add -A && git commit

# 3. 测试（能打开网页、能听书、能上传）

# 4. 推送
git push origin master

# 5. 出包（见第四节"打补丁包"）
```

## 四、自己改代码后上线（不打上游）

### ⚠️ 先搞清在哪操作

| 你要做的事 | 在哪做 | NAS 上能做吗 |
|---|---|---|
| 改代码、git 提交、推 Gitee、出成品包 | **开发侧**（沙箱 `/root/work/audiobook-src`，或你的 Windows 电脑） | ❌ 不能，NAS 上没装 git 仓库 |
| 收包、upgrade.sh 升级 | **NAS**（`/volume1/docker/`） | ✅ 只能在这做 |

一句话：**开发侧改代码 + 出包，NAS 只负责收包和上线。**
下文中标注「开发侧」的步骤在 NAS 上不要执行（会报 `cd: no such file`）。

**如果你想走"方式 1（让 AI 改）"，本章你只需要看的步骤是**：
步骤 1~3 直接跳过（AI 帮你做），你做**步骤 4（下载包传 NAS）→ 步骤 5（NAS 上跑）→ 步骤 6（验证）**。

### 流程总览

```
【开发侧】改代码 → 提交 → 推 Gitee → 出成品包
                    ↓ 传到 NAS
【NAS】upgrade.sh 上线 → 浏览器验证
```

### 步骤 1【开发侧】：改代码并提交

**走方式 1（AI 改）**：跳过本节，直接在对话框里说需求即可。

**走方式 3（自己改）**：

```sh
cd /root/work/audiobook-src        # 沙箱路径；Windows 上是 D:\audiobook-src
git status                     # 看改了哪些
git add 改动的文件
git commit -m "说明你改了什么"
```

> 没有这个目录就先 clone：`git clone https://gitee.com/wxgoo/audiobook-src.git`

### 步骤 2【开发侧】：推送 Gitee

```sh
git push origin master
```

如果报 `could not read Username`，用带令牌的写法：

```sh
git push https://wxgoo:df1901c0825241bcc94aa54e6608fc2b@gitee.com/wxgoo/audiobook-src.git master
```

### 步骤 3【开发侧】：出成品包

**用 `scripts/pack.sh`，不要自己 `tar`。** 一条命令出包并验包：

```sh
cd /root/work/audiobook-src
sh scripts/pack.sh                 # 版本号自动取 CHANGELOG 顶部的「当前」版本
sh scripts/pack.sh 4.6.0-11        # 或手动指定

# 已经有包想验一下
sh scripts/pack.sh --check /workspace/audiobook-deploy-4.6.0-11.tar.gz
```

它依次做：源码污染自检 → 产物自检 → 打包 → **解压实数符号链接**再验一遍。
任一步不过就 `exit 1`，不会产出一个坏包。

> ⚠️ **为什么不能自己 `tar --transform`**：`myreader-dist` 里有 127 个符号链接，
> 内容是相对路径 `../../../../node_modules/.pnpm/...`。`--transform` 的替换规则会
> 连带作用于**链接的目标内容**，把它改成 `audiobook./../../../node_modules/...`，
> 结果包能解开、文件数也对，但链接全断 —— 部署后 `/readerx` 全 502。
> 这个坑已经踩过一次，`pack.sh` 用 `cp -al` + `cd 父目录 tar` 绕开了它。
>
> 详细原理见 [`scripts/README.md`](../scripts/README.md) 的「出包」一节。

正常成功的输出长这样：

```
==> [2/4] MyReader 产物自检
  2732 条，有效链接 119
==> [4/4] 验包
  myreader-dist: 2732 条, 有效链接 119, 断链 8
  ✅ 校验通过
```

断链 8 个是产物固有的历史残留，`deploy.sh` 也认这个数，不影响运行。

### 步骤 4【手工传文件】：成品包传 NAS

把 `audiobook-deploy-<版本>.tar.gz` 上传到 `/volume1/docker/`。

> **不需要打补丁**。`merge-patchN.sh` 那套「补丁包 + 基准包 → 成品包」的流程已经废弃：
> 现在开发侧直接出完整成品包，NAS 上只负责装。老旧文档里若还写着
> `audiobook-patch-*.tar.gz` / `merge-patch3.sh`，按本总纲为准——
> 那两个文件在仓库和 NAS 上都已经不存在了。

### 步骤 5【NAS】：上线

```sh
sh /volume1/docker/audiobook/scripts/upgrade.sh /volume1/docker/audiobook-deploy-<版本>.tar.gz
```

脚本自动：备份数据库 → 停容器 → 旧源码改名 → 解压新源码 → 校验 → 构建 → 启动 → 验证 4 个进程。

### 步骤 6【浏览器】：验证

浏览器打开网页，**Ctrl+F5 强刷**（清缓存），检查改动是否生效。

### 常见报错对照

| 报错 | 原因 | 解决 |
|---|---|---|
| `could not read Username` | 没带令牌 | 用上面带令牌的完整地址 |
| `dubious ownership` | 目录属主不对 | `git config --global --add safe.directory 路径` |
| `rejected / non-fast-forward` | 远程有你本地没有的提交 | `git fetch` → `git rebase FETCH_HEAD` → 再 push |
| `Author identity unknown` | 没配用户名邮箱 | 见上方"一次性准备" |
| `403` | 令牌失效 | Gitee 重新生成，替换脚本里的 TOKEN |

## 六、重装 / 换新机器

```sh
cd /volume1/docker
sh /volume1/docker/audiobook/scripts/upgrade.sh /volume1/docker/audiobook-deploy-<版本>.tar.gz
```

如果是全新机器（`audiobook/` 目录都不存在），先临时解出 upgrade.sh：

```sh
cd /volume1/docker
rm -rf /tmp/boot && mkdir /tmp/boot
tar -xzf audiobook-deploy-<版本>.tar.gz -C /tmp/boot
sh /tmp/boot/audiobook/scripts/upgrade.sh /volume1/docker/audiobook-deploy-<版本>.tar.gz
```

前提：`audiobook-data/` 目录要先存在（空了也行，会重建）。

## 八、绝对不要做的事

| ❌ 禁止 | 原因 |
|---|---|
| `rm -rf /volume1/docker/audiobook-data` | 11GB 数据全没，没有第二次机会 |
| 把 books/、音频拷进 `audiobook/` 目录 | 下次升级会丢，且污染源码 |
| 直接从 Gitee 下载 zip 部署 | 符号链接丢失，网页会白屏 |
| 群晖 SSH 里粘贴多行命令 | BusyBox 会逐行执行，前半句就跑飞了 → 写成 .sh 文件再 sh |
| 用 `tar --exclude` 打包 | 群晖 BusyBox tar 不认，直接报空包 |

## 九、常用工具入口（4.6.0-15 起）

### 音频批量转码

侧栏 **管理 → 音频转码**，或直接访问 `/toolbox/audio_transcode`。

把书 `.audio/` 里的 mp3 批量转成 m4a（AAC）。做两件事：洗掉 mp3 内嵌的
杂乱 ID3 标签（`-map_metadata -1`，避免播音员名被当作者）、`+faststart`
让浏览器秒开可拖。

| 场景 | 怎么做 |
|---|---|
| 转一本书 | 输入书籍 ID（书详情页地址 `/book/215` 里的数字）→ 扫描单本 → 选码率 → 开始 |
| 转多本 | 点「扫描全库（批量）」→ 勾选要转的书（默认全选）→ 选码率 → 开始 |
| 看进度 | 工具页实时显示当前书、总进度、失败明细；页面关掉后台照跑，重开工具页即可看 |

要点：

- **转成功的才删 mp3**，失败的 mp3 保留并在结果里列出原因，可修好后重跑
- 已有同名 m4a 会被新转的覆盖；已是 m4a 的不会出现在扫描结果里
- 同一时刻只允许一个转码任务
- 码率：语音类 64k 足够（体积小、网络盘播放更顺），音乐类选 128k
- 65 集 20 分钟的音频，NAS 上约 15–30 分钟

### 「目录」功能（多层分类）

侧栏 **目录**（文件夹图标），受两个开关控制：

| 开关位置 | 作用 |
|---|---|
| 管理 → 系统设置 → 扩展功能 →「启用以目录进行多层分类的功能」 | 总开关（配置项 `ENABLE_FOLDER_BROWSE`）。关闭时侧栏不显示「目录」，书详情页也不显示目录标签 |
| 管理 → 系统设置 → 侧边栏显示项目 → 勾选「目录」 | 只管**侧栏是否显示入口**，不影响功能本身 |

用法：目录是 calibre 自定义列 `#folder`，格式 `一级.二级`（最多 2 级，每级
不含标点，≤24 字）。在**书详情页**点橙色的「目录 : 未设置」标签 → 输入路径 →
保存。侧栏「目录」里按层级浏览，点进去看该目录下的书。管理员还能在目录页
重命名整条路径。

> 注意：详情页某些书会自动带上目录值——那是导入/提取时 `tools/category_backfill.py`
> 或批量编辑写入的，属于正常现象，不是误点。
