## 4. 值得动手的：我们有能力但没接线（★ 本轮建议做）

### 4.1 模块化门控接线（上游 57 处，我们 0 处）—— ✅ **本轮已完成**

**现状**：我们已有 `webserver/base/modules.py`（模块表、`module_enabled`、`snapshot`、
`ModuleGateMixin` 全套都在），但**没有任何 handler 使用 `ModuleGateMixin`**——
只有 docstring 里的示例代码。

**上游的接线点**（`git grep "ModuleGateMixin," webserver/ | grep class` 实测 57 处）：

| 文件 | 门控的 handler 数 | 模块 |
|---|---|---|
| `webserver/handlers/audio.py` | 9 | `MODULE_AUDIO`（有声书） |
| `webserver/handlers/booklist.py` | 11 | `MODULE_SHARED_READING` |
| `webserver/handlers/admin.py` | 4 | `MODULE_AI` / `MODULE_COMMUNITY` / `MODULE_MULTIUSER` |
| `webserver/handlers/podcast.py` 等 | 其余 | podcast / TTS / 音频导入 |

**为什么值得做**：上游的口径是「一个模块 = 一个勾选框：关掉后**入口消失、设置不渲染、
接口拒绝**，数据只隐藏不删除」。我们现在是**勾选框存在但开了没用**——用户勾了"关闭有声书"，
接口照样能调。这不是"没这功能"，是"功能半成品"。

**风险**：接线会改变接口行为（关掉模块后接口 404/拒绝）。需要确认现有站点的
`ENABLE_MODULE_*` 默认值都是开着（`settings.py` 默认 True），接上线不会影响默认行为。

## 6. 冲突文件的处理原则

**58 个冲突文件里，我们改得比上游多的占绝大多数**（如 `audio.py` 我们 8 个提交 vs 上游 1 个）。
逐个看是浪费，正确做法是**按能力缺口分类处理**：

| 类别 | 处理 |
|---|---|
| 上游只加了模块门控，我们改了很多 | **只搬门控那几行**（`class X(ModuleGateMixin, BaseHandler)` + `module_id = MODULE_AUDIO`），其余保留我们的 |
| 上游加了新功能 UI（三语文案 + 组件） | 移植该功能时**连带搬三语文案**；不移植就不搬 |
| 上游的纯 bugfix | 单独挑出来核实我们是否已等价实现，已实现则不搬 |
| 依赖锁文件 / 二进制 / 上游元信息 | 不碰 |
