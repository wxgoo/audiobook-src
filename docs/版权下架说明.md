# 版权下架说明（4.6.0-build.27-r8）

> 适用场景：**版权人要求某本书下架，不得再提供阅读和下载**。
> 本功能做的是「书还在，但拿不到正文」——不删书、不删文件、不隐藏书目，
> 读者在详情页与各个入口都会看到版权声明，并被引导购买正版。

---

## 1. 读者会看到什么

| 位置 | 表现 |
|---|---|
| 图书详情页 | 顶部橙色声明卡片，正文为「因版权人要求，已下架处理，请购买正版图书支持原作者！」；书名、作者、封面、简介仍可看 |
| 点「阅读」「下载」 | 弹出版权声明；按钮不再是静默置灰，避免误以为站点坏了 |
| 直接打开 `/read/<id>`、下载直链 `/api/book/<id>.<fmt>` | 403 + 自包含的 HTML 版权声明页，不会被下载器存成假书 |
| 已打开的阅读器（MyReader / epub.js） | 拿不到正文分片与物理路径，翻页直接失败，无法继续读 |
| 分享链接 `/s/<token>` | 分享页显示声明，不下发任何文件链接，不给 `book_id` |
| WAP 老设备页面 | 格式链接位置改显示版权声明，不再给下载直链 |
| OPDS / WebDAV 目录 | 这本书不出现在目录里，客户端不会列出无法获取的书 |

**仍然可见**：书目信息、封面 / 缩略图、作者、分类、标签、评论、阅读统计、书架里的条目。
下架不等于销毁，这样既满足「不得提供阅读和下载」，也能把「请购买正版」的引导放到读者眼前。

---

## 2. 管理员怎么操作

三个入口，任选其一：

1. **图书详情页 → 「管理」菜单 → 「版权下架」/「恢复上架」**
   下架时可填「下架原因」（内部留痕，读者看不到），确认后立即生效。
2. **左侧管理树 → 「版权下架」**（`/admin/takedowns`）
   集中查看全部已下架图书，支持按 `book_id` 新增、单本恢复、勾选批量恢复，
   页面顶部显示当前生效的版权声明文案。
3. **管理 API**（仅管理员，供脚本 / 自动化调用）

```bash
# 列表
curl -b cookies.txt "http://<站点>/api/admin/takedown/list"

# 单本下架
curl -b cookies.txt -X POST -H 'Content-Type: application/json' \
  -d '{"book_id": 123, "reason": "版权方 2026-11-09 来函，编号 XXX"}' \
  "http://<站点>/api/admin/takedown/set"

# 批量下架（上限 200 本）
curl -b cookies.txt -X POST -H 'Content-Type: application/json' \
  -d '{"book_ids": [123, 124], "reason": "同批来函"}' \
  "http://<站点>/api/admin/takedown/set"

# 恢复（单本 / 批量）
curl -b cookies.txt -X POST -H 'Content-Type: application/json' \
  -d '{"book_id": 123}' "http://<站点>/api/admin/takedown/remove"
```

下架 / 恢复**立即生效，不需要重启容器**；服务内部有 60 秒缓存，但写操作会同步刷新。

## 3. 后端到底拦了哪些出口

统一门禁挂在 `BaseHandler.prepare()`（`webserver/handlers/base.py`），由
`webserver/services/book_takedown.py` 从路径里解析出 `book_id` 后判定。
**判定发生在 Python 设置 `X-Accel-Redirect` 之前**——一旦交给 nginx `/_lib/` 直出，
Python 就没有第二次机会了，所以顺序不能改。

| 出口 | 路径形态 | 拦法 |
|---|---|---|
| 下载直链（含 OPDS 直链） | `/api/book/<id>.<fmt>` | 403 HTML 声明页 |
| 阅读页 / 阅读 API | `/read/<id>`、`/api/book/<id>/read` | 403 HTML / 200 JSON 错误 |
| epub 正文分片 | `/get/extract/<id>/...` | 403 HTML 声明页 |
| TXT 正文 | `/api/read/txt/<id>` | 200 JSON 错误 |
| MyReader 物理路径 | `/api/book/<id>/filepath` | 200 JSON 错误（MyReader 拿不到路径就打不开书） |
| 格式转换 / 转 PDF / 盖章 / 写回 | `convert`、`topdf`、`addstamp`、`savemeta` | 200 JSON 错误 |
| 邮件推送 / 推送设备 | `mailto`、`send_to_device` | 200 JSON 错误 |
| 有声书音频 | `/api/audio/<id>/<file>.mp3`、`/api/audios/<id>/collection/download`、播客音频 | 403 HTML 声明页 |
| OPDS 目录 | `/opds/...` | feed 里剔除下架书；缓存的旧直链仍被上表拦住 |
| WebDAV | `/books/...` | 目录剔除 + `get_content()` 抛 `HTTP_FORBIDDEN`（WSGI 旁路，不经过 Tornado 门禁） |
| MCP `download_book` | MCP 请求体带 `book_id` | 服务内显式返回 `code=book.copyright_takedown` 的错误 |
| MyReader（Next.js，nginx 独立反代） | `/readerx/open` | 它必须回源 `/api/book/<id>/filepath` 取物理路径，该接口已被拦，因此读不到文件 |

> **响应分流的原因**：aria2 / IDM / epub.js 会把 `200 + JSON` 当成"资源拿到手"存成假书，
> 所以文件类出口一律 `403 + text/html + Cache-Control: no-store`；
> 只有前端 `$backend` 调用的 JSON 接口才用 `200 + err=book.copyright_takedown`，
> 这样前端能拿到文案弹提示。

**故意不拦的路径**：`/api/book/<id>` 详情、封面 / 缩略图 / OPF 元数据、
编辑与删除、收藏 / 想读 / 阅读状态、左侧树统计、下架管理接口本身。
这些不提供正文，拦掉反而会让详情页无法显示声明、列表全是破图。

## 4. 数据存在哪、怎么备份

- 表：`book_takedowns`，在本站自己的 SQLite 库
  `/data/books/calibre-webserver.db` 里，**不在 Calibre 的 `metadata.db` 里**。
- 字段：`book_id`（主键）、`title`（下架时书名快照）、`reason`、
  `operator`、`operator_id`、`create_time`。
- 建表：`models.ensure_new_tables()` 用 `checkfirst=True` 幂等补建，
  `docker/start.sh` 每次启动都会跑，**零手写迁移、零 ALTER TABLE**。
- 备份：随 `/data/books/` 整体备份即可（与用户、分享、阅读统计同一份库）。
  恢复旧备份会把下架记录一起回滚到备份时刻的状态，这是预期行为。
- 删除书籍时：Calibre 侧的书没了，下架记录会留在表里成为孤儿行，不影响功能；
  管理员可在 `/admin/takedowns` 里手动恢复/清理，或直接删该行。

## 5. 自定义版权声明文案

默认（中文）：

```
因版权人要求，已下架处理，请购买正版图书支持原作者！
```

运维可在站点配置里覆盖：

```python
CONF["COPYRIGHT_TAKEDOWN_NOTICE"] = "本书已按版权方要求停止提供在线服务，请支持正版。"
```

覆盖值会用于：详情页 / 分享页 / WAP 的下发文案、403 HTML 声明页、各 JSON 错误体。
输出前统一 `html.escape`，可安全填写含特殊字符的文案。前端三语 locale 里的
`book.copyrightNotice` 只是后端没有下发文案时的兜底，优先用后端值。

## 6. 与在线更新 / 重新部署的关系

- 下架记录存在**数据卷**（`/data/books/`），不在镜像里。重建容器、升级镜像、
  执行 `deploy.sh` / `upgrade.sh`、页内在线热更新都**不会**清掉下架标记。
- r8 本身含前端产物 `app/dist` 的改动，发布清单是
  `requires_dist=true` / `hotfixable=false`：「版本与更新」页会给出**重新部署命令**，
  不能用页内「立即更新」代替。首次上 r8 请完整部署一次。

## 7. 常见情况

| 现象 | 原因 / 处理 |
|---|---|
| 下架后某客户端还能翻几页 | 本地缓存 / 已下载整本 epub。清空该客户端缓存即可；服务端不再吐任何新分片 |
| 详情页封面变破图 | 不应该发生，封面路径不在拦截清单里。检查是不是 REQUIRE_LOGIN 或 CDN 配置问题 |
| `/readerx/open?bookId=...` 直接输地址显示 404/502 | 拿不到 `/filepath` 的预期结果，正文不会泄露；正常从详情页点阅读会先看到版权声明 |
| 想让下架书从列表里彻底消失 | 当前设计刻意保留书目以展示声明。如确需隐藏，请走删除书籍流程（会删文件，不可恢复） |
| 恢复后仍提示下架 | 强制刷新详情页（服务端写操作已清缓存）；若仍有，检查是否有反向代理缓存了旧 JSON |
