# 真机验证清单（NAS 部署后逐项点检）

> 用途：任何**结构性变化**的包（尤其 `pack.sh --slim` 产出的瘦身包，排除了 `app/node_modules`）
> 在对外发布前，必须按本清单在真机逐项点检并留痕。未全部 PASS 的包不得作为发布包。
>
> 背景口径：`app/node_modules` 默认**保留**（与历史上能跑通的 r26/r27 包同构）；`--slim`
> 只是候选瘦身方案，不预设「已确认无用」。过去几次按「看着没用」删除都出现过运行异常，
> 因此这里所有结论以真机点检为准，不靠代码推理。
>
> 约定：下文 `<id>` 为书籍/音频 ID，`<容器>` 为实际容器名（`docker compose` 默认
> `audiobook-mybooks-1`，以 `docker ps` 为准），`<端口>` 为映射到宿主机的端口。

## 0. 验收前准备（5 分钟）

| 步骤 | 命令 / 做法 | 说明 |
| --- | --- | --- |
| 记录包指纹 | `sha256sum audiobook-deploy-*.tar.gz` | 结果写进结果表，出问题时可确认「验的是不是同一个包」 |
| 留退路 | 备份 `audiobook-data/`；`docker images` 记下当前可用镜像 tag | 失败时能回滚到上一版 |
| 起容器 | `docker compose down && docker compose up -d --build` | 构建日志另存：`docker compose logs --no-color > build.log` |
| 看构建快路 | 在 `build.log` 里搜 `预构建 dist：有` 与 `跳过 npm ci 与 generate` | 这两行缺失说明镜像走了现场构建，行为已与发布口径不同 |
| 等服务就绪 | 浏览器打开首页，直到能正常出书 | 首次启动要等 DB 迁移，期间 502/空白属正常 |

日志位置（容器内）：

- Tornado 主服务：`/data/log/mybooks.log`
- MyReader（Next.js）：`/data/log/myreader.log`
- nginx：容器 stdout（`docker logs <容器>`）

一条命令抓全部异常：

```bash
docker logs --tail 500 <容器> 2>&1 | grep -E "Traceback|ERROR|Exception| 500 | 502 "
docker exec <容器> sh -c 'tail -200 /data/log/myreader.log' | grep -E "Error|Cannot find module|ECONNREFUSED"
```

## 4. 失败处理

1. 任一项 FAIL：**不要**继续发布，也不要试着删包内其他「看着没用」的目录来救。
2. 保留现场：`docker compose logs > fail.log`，导出 `/data/log/mybooks.log`、`/data/log/myreader.log` 尾部。
3. 回滚：换回上一版镜像 tag 或旧部署包，`docker compose up -d --build`，确认首页与阅读器恢复。
4. 记录：把 FAIL 项、日志关键字与复现步骤写进交付记录，作为下一轮修复的输入。
