## 一、技术栈与架构总览

```
┌────────────────────────────────────────────────────┐
│  浏览器 / MyReader / OPDS / WAP / 移动 App          │
└────────────────────┬───────────────────────────────┘
                     │ nginx (反代 + 静态 + 444 屏蔽)
┌────────────────────▼───────────────────────────────┐
│  Tornado (webserver/main.py)                       │
│  ├── handlers/    ← 路由 + 请求处理                 │
│  ├── services/    ← 业务逻辑 + 后台任务              │
│  ├── plugins/meta/← 信息源插件（刮削）               │
│  ├── toolbox/     ← 工具箱工具                      │
│  ├── worker/      ← epub→audio 转换 worker           │
│  └── base/        ← BaseHandler + 公用基础设施       │
├────────────────────────────────────────────────────┤
│  Calibre LibraryDatabase (metadata.db)              │
│  + SQLite (calibre-webserver.db: 用户/权限/进度等)   │
├────────────────────────────────────────────────────┤
│  Vue 2 SPA (app/dist/, 预构建进包)                   │
│  MyReader (myreader-dist/, Next.js standalone)      │
└────────────────────────────────────────────────────┘
```

**一句话**：Tornado 单进程事件循环，Calibre 管书库数据，SQLite 管用户数据；
前端 Vue 2 预构建进包不走 NAS 构建；MyReader 是内嵌的 Next.js 阅读器。

### 后端装配与关键约定（原 `CLAUDE.md` 架构段迁入）

`webserver/main.py` 的 `main()` 依次装配：

- Calibre 书库（`legacy` book_db + `cache` 新式缓存），从 `--with-library` 打开；
- 应用自己的 SQLAlchemy `ScopedSession`（`user_database` 设置，独立于 Calibre 库）；
- 对 Calibre 内部打补丁（关掉 Qt GUI 依赖、绑定 top-dir 书名等），见 `config_calibre()` 与 `gui2.must_use_qt`；
- 由各 `webserver/handlers/` 模块的 `routes()` 拼出 `tornado.web.Application`。

**路由顺序有价值**，因为存在 catch-all：

1. social auth，然后各功能路由（`assistant`、`mcp`、`admin`、`barcode`、`scan`、`opds`、`book`、`user`、`meta`、`audio`、`toolbox`、`podcast`）；
2. WAP 路由（e-ink/Kindle 服务端渲染页），**必须排在静态文件之前**；
3. WebDAV（`/books/?(.*)`）；
4. `static_files.routes()` 最后 —— 它含 `r"/(.*)"`，兜底发 Vue SPA。

podcast / WebDAV / AI assistant 等总是注册，但请求时才看 `ENABLE_*` 开关，所以在后台开关立即生效、无需重启。

**设置是分层字典**：`webserver/settings.py` 默认值 ← `auto.py`（机器生成）← `manual.py`，后两者从
`settings_path`（默认 `/data/books/settings/`）加载；统一用 `webserver.loader.get_settings()`（别名 `CONF`）。
`settings.py` 里已有的值不要在业务代码里硬编码。

**两个数据库并存**：Calibre 库（books/authors/tags…）走 `legacy`/`cache`，不经过本项目 SQLAlchemy 模型；
应用库（`user_database`）由 `webserver/models.py` 定义 `Reader`、`Item`、`Message` 等。
`bind_session()` 把同一个 session 接到 `Base` 与 `SQLAlchemyMixin`（social-auth 模型）上。

**Handler 与 Service**：每个 handler 模块末尾 `routes()` 返回 URL 列表；`handlers/base.py` 的 `BaseHandler`
提供 `@js`（捕获异常 + JSON 化 + 统一 CORS/缓存头）与类级 `db_lock`（`threading.RLock`，串行化线程不安全的
Calibre 访问）。重业务放 `webserver/services/`（`BookBarnService`、`AsyncService`、`ItemSyncService`、
`ScanService`、`MonitorService` 等），handler 只做转发。

**i18n**：后端 `webserver/i18n.py` + `webserver/i18n/`（`_()`、`choose_language()`、`set_language()`）；
前端 `vue-i18n`，语言包在 `app/locales/`。

## 二、代码导航（改一个功能要碰哪些文件）

| 要改什么 | 核心文件 | 备注 |
|---|---|---|
| 页面路由 / API | `webserver/handlers/*.py` | 每个模块一个文件，末尾 `routes()` 函数注册 |
| 业务逻辑 | `webserver/services/*.py` | AsyncService 子类或独立类 |
| 信息源插件 | `webserver/plugins/meta/*/plugin.py` | 见下文「新增信息源插件」 |
| 工具箱工具 | `webserver/toolbox/*_tool.py` + `app/src/pages/toolbox/*.vue` | 见 `document/toolbox_design.md` |
| 有声书播放 | `app/src/pages/audio/_id.vue` | 播放器 + 进度 + 字幕，1800+ 行 |
| 有声书转换 | `webserver/worker/epub2audio_worker.py` + `webserver/epub_to_audio/` | subprocess 调 edge-tts |
| 设置项 | `webserver/settings.py`（默认值）+ `webserver/base/setting_saver.py`（白名单）+ `app/src/pages/admin/settings.vue`（UI） | 三处必须同步 |
| 版本号 | `webserver/version.py` + 6 个载体 | 用 `--set` 一条命令，见下文 |
| 备份 | `scripts/backup.sh` + `scripts/backup_run.py` | |
| 检索索引 | `webserver/services/search_index.py` | FTS5，独立 .db |
| 听书进度 | `webserver/handlers/audio.py` AudioPlaybackProgress + `models.py` AudioPlayback | |
| 读者组权限 | `webserver/handlers/reader_group.py` + `webserver/services/reader_group.py` | 叠加在既有 `read_limit`/`limit_tags` 上，零 DB 迁移：组定义在 `CONF["READER_GROUPS"]`，成员关系在 `Reader.extra["reader_group"]` |
| 语音转写 | `webserver/handlers/transcribe.py` + `webserver/services/transcribe.py` | 可选 Whisper，`whisper_available()` 门控，进度走 BackgroundService |

### settings.vue 的 groups 配置

设置页是数据驱动的：`this.groups` 数组定义分组/节/字段/嵌套组/special 块。
改设置 UI 只动这个数组 + locale + 搜索别名表（`al` 字段），保存/脏跟踪自动适配。

**已归堆（build.27-r11）**：`users-access`（访问控制与读者组）、`users-reg`（注册、邀请与新用户）。
不再有单独的 users-guest / users-default / reader-groups 卡。

## 三、数据库

### calibre metadata.db（书库）

| 表 | 用途 | 注意 |
|---|---|---|
| `books` | 书目主表 | **没有** `publisher` / `series` 列（见踩坑 #1） |
| `books_authors_link` + `authors` | 作者（多对多） | |
| `books_tags_link` + `tags` | 标签（多对多） | |
| `books_publishers_link` + `publishers` | 出版社（多对多） | |
| `books_series_link` + `series` | 丛书（多对多） | |
| `comments` | 简介 | 正常一书一条，但老库可能多行——JOIN 后聚合去重 |
| `custom_columns` | 自定义列（`#narrator` 等） | 由 calibre API 管理 |

### calibre-webserver.db（应用数据）

| 表 | 用途 |
|---|---|
| `readers` | 用户（`extra` JSON 存读者组归属） |
| `readings` / `book_reading_stats` | 阅读进度与统计 |
| `audio_playback` | 有声书播放进度（跨设备续播） |
| `scanfiles` | 扫描导入记录（`hash` 防重、`audiodir:` 标记） |
| `biz_key` | 下载 / 合集导出的临时密钥 |
| `messages` | 站内消息 |
| `koreader_position` | KOReader 阅读位置同步 |

### 启动时自动建的表

`models.py` 的 `_NEW_TABLES_AUTO_ENSURE` 元组列出的表随启动 `create_all(checkfirst=True)` 幂等创建。
新增表时加进这个元组即可，不需要用户手动 `--syncdb`。

## 四、常见开发任务

### 4.1 新增一个信息源插件

1. `webserver/plugins/meta/<name>/` 新建目录：`__init__.py`（re-export）+ `plugin.py` + `api.py`
2. `plugin.py` 继承 `MetaSourcePlugin`，实现 `search(title, isbn, publisher)` 和可选 `search_best(mi)`
3. `SOURCE_KEYS = (META_SOURCE_XXX,)`，`PROVIDER_KEY = KEY`
4. `webserver/services/book_search.py` 的 `_PLUGIN_CLASSES` 加上插件类
5. `webserver/constants.py` 加 `META_SOURCE_XXX = "xxx"`
6. 设置页 `settings.vue` 的 `meta_sources` 多选自动出现（来源走 `all_sources()`）
7. `webserver/settings.py` 加默认源列表（`META_SELECTED_SOURCES`）和限流键
8. 三语 locale 补标签

⚠️ **calibre schema**：查 metadata.db 时出版社/丛书走链接表（见踩坑 #1），不要假设 books 表有这些列。

### 4.2 新增一个 handler 路由

1. `webserver/handlers/<module>.py` 新建类继承 `BaseHandler`
2. 用 `@js` 装饰器（统一 JSON 输出 + CORS + 异常处理）、`@auth` / `@is_admin` 做鉴权
3. 末尾 `routes()` 返回 `(r"/api/...", HandlerClass)` 列表
4. `webserver/main.py` 的 `names` 列表加模块名（如果新建了 .py 文件）

### 4.3 新增一个工具箱工具

见 [`document/toolbox_design.md`](../document/toolbox_design.md)。概要：

1. `webserver/toolbox/<name>_tool.py` 继承 `ToolBase`，声明 `tool_id` / `name`
2. `webserver/toolbox/toolset.py` 注册
3. `app/src/pages/toolbox/<name>.vue` 前端页面
4. `webserver/handlers/toolbox.py` 或独立 handler 暴露 API

### 4.4 新增设置项

1. `webserver/settings.py` 加默认值
2. `webserver/base/setting_saver.py` 的 `ADMIN_SETTING_KEYS` 加键名（不加则保存被静默丢弃）
3. `app/src/pages/admin/settings.vue` 的 `groups` 配置加字段定义
4. 三语 locale 补 label / tips
5. 需要重启才生效的键加进 `RESTART_REQUIRED_KEYS`

### 4.5 版本升号

```sh
python scripts/check-version-lock.py --set 4.6.0-build.<N>
```

一条命令改全部九处载体（version.py / compose / Dockerfile / package.json /
package-lock / Makefile / 校验器常量 / README 示例 / tests 字面量），改完自动复检。
CHANGELOG 版本条目**人工写**（pack.sh 从首条标题取号）。

### 4.6 发布一个修订

```sh
# 1. 改代码 → py_compile → 更新 CHANGELOG
# 2. 提交推送
git add -A && git commit && git push
# 3. 出清单（纯后端 .py 改动 → requires_dist=false 可页内热更）
python3 scripts/gen-update-manifest.py \
  --revision 4.6.0-build.27-r27 --base-revision 4.6.0-build.27-r26 \
  --base-commit <r26 的 commit sha> --summary "..." --notes "..."
# 4. 提交推送 manifest
# 5. NAS 上点「立即更新」（纯后端）或整包部署（含前端/镜像级）
```

推送 Gitee 的凭据只用环境变量 `GITEE_TOKEN` 或 `~/.netrc`（600 权限）提供，
不要写进 URL、脚本、文档或提交内容（`scripts/upgrade-upstream.sh` 同样只读该环境变量）。

## 五、关键设计决策与原因

### 版本检测与在线更新

`update/manifest.json` 是唯一发布源（Gitee raw 直链），按修订号 `-rN` 比对。
纯后端 `.py` 改动可页内热更（下载→sha256 校验→原子替换→自动重启）；
含前端产物必须重新部署。详见 [`docs/在线更新说明.md`](在线更新说明.md)。

### 有声书音频跟着书目录走

音频放 `library/<作者>/<书名> (id)/.audio/`，与电子书同目录。
旧布局 `audios/<id>/` 已废弃（4.6.0-13 起），`upgrade.sh` 自动迁移。

### 播放进度三层

| 层 | 存储 | 范围 |
|---|---|---|
| localStorage | 浏览器本地 | 同浏览器关了再开能恢复 |
| 服务端 `audio_playback` | 数据库 | 跨设备续播 |
| KOReader 同步 | koreader_position | 电子书阅读位置（有声书未接入） |

前端 `tryRestoreFromServer()` 做「谁新用谁」仲裁（`client_ts` 时间戳）。

### 读者组三层权限

```
REQUIRE_LOGIN（门槛：谁能进）
  └→ ALLOW_READ_RANGE_SETTING（总开关：是否启用阅读范围控制）
       └→ READER_GROUPS_ENABLED（读者组开关：组规则是否生效）
            └→ 用户自身 read_limit / limit_tags（个人设置，优先于组）
```

#### 加一套读者组模板

模板只有一处数据源：`webserver/services/reader_group.py` 的 `PRESET_GROUPS`。
加一条 = 加一个 dict，前端不用改（模板菜单按 `group` 字段自动分栏，顺序取数组先后）。

- `mode` 只能是 `whitelist` / `blacklist` / `open`。**要表达「不受限制」只能用 `open`**：
  白名单留空在严格模式下等于一本书都看不到（「成人家属」当初就是这么坏掉的）。
- 条件一律写在 `tags`，`categories` 留空 —— `#category` 自定义列在多数书库是空的，
  拿它做模板会静默失效（`test_presets_never_use_categories` 锁着）。
- 同一栏的模板必须连续，中间插一条别栏的，前端会把这一栏拆成两个同名小标题
  （`test_preset_groups_are_contiguous` 锁着）。
- 标签名照通用书库写就行，对不上不致命：界面会比对 `/reader_groups/options` 的真实
  标签并提示「本库缺少 N 项」，还能一键剔除。但**别写只在自己库里存在的私有标签**当模板。

## 六、踩坑清单（每次都看，血泪教训）

### 1. calibre books 表没有 publisher / series 列

出版社/丛书走 `books_publishers_link` / `books_series_link` 链接表。
直接写 `b.publisher` / `b.series` 真库必炸 `no such column`（build.27-r12 修复）。

### 2. FTS5 重复 rowid = constraint failed

FTS5 虚拟表 INSERT 时 rowid 已存在会报错（不是 REPLACE）。
JOIN 产生多行的场景（多评论/多链接）必须先聚合去重。

### 3. CRLF：Windows 工作区 ≠ git 仓库 ≠ Gitee raw

Windows 检出是 CRLF，git 仓库 / Gitee raw 是 LF（`.gitattributes` 强制）。
任何按工作区文件计算哈希/行数/字符串匹配的代码，在真库上都会出错。

已出过的事故：
- version.py CRLF → `check-version.sh` 五版本号比较全部「假 FAIL」（build.26）
- `check-version-lock.py --set` 写 version.py 为 CRLF（根因，build.26 断源修复）
- 清单哈希按工作区 CRLF 计算 → NAS 热更 sha256 必失败（build.27-r12）

**规则**：读文件用 `newline=""`（不转义），写文件用 `newline="\n"`（强制 LF），
哈希 / 字节比对 / 正则匹配统一按 **git blob**（`git show HEAD:<path>`）而不是磁盘文件。

### 4. myreader-dist 的 119 根符号链接

Next.js standalone 产物靠三层符号链接解析依赖。Windows 检出 / GUI 解压会压扁。
`deploy.sh` / `upgrade.sh` 构建前自动按清单校验并重建（`check-myreader-links.sh --fix`）。
**从 Windows 直接打包会压扁**——出包必须在 Linux/NAS 上跑 `pack.sh`。

### 5. Tornado 事件循环不能阻塞

handler 里同步做网络请求 / 大文件 IO / subprocess / time.sleep 会冻住全站。
阻塞操作丢进 `utils.run_in_threadpool` 或 `run_in_executor`。
`@js` 装饰器支持 `async def`，Tornado handler 原生支持协程。

已修的现场：ffprobe 200 次（build.21）、EPUB 整本读写（build.21）、
save_book_meta（build.21）、zip 打包（build.27-r12）。

### 6. 并发写 SQLite 必须走队列或锁

calibre 写 `metadata.db` 是单写者模型，多线程并发导入会让事务互等。
Phase2 攒批 + 短写事务 + worker 单线程是正确设计，不要改成多 worker。

### 7. 响应式数据不要放 Audio / Media 元素

Vue 2 把 Audio 元素上的事件回调做成响应式依赖后，任何 timeupdate 都会触发
整棵子树重新求值——表现为进度条被按住不动、状态灯疯狂闪烁。
播放器实例挂 `this._el`（非响应式），回调只做纯赋值。

### 8. douban-rs-api 伴生容器

豆瓣 v1 信息源需要一个 sidecar 容器（`douban-api-rs`），单容器/vDSM 部署
通常没有。未配置 `douban_baseurl` 时插件跳过（build.27-r12 起）。
douban_v2 直连 book.douban.com 不需要容器，是实际在用的豆瓣源。

### 9. `app/dist` 必须完整入库：`.gitignore` 里的 dist 规则已删

`app/.gitignore` 曾带两条模板规则（Node 模板 `/dist` + Nuxt 模板 `dist`），
把 `app/dist/_nuxt/*.js` 全挡在仓库外。仓库里只剩 html/css/fonts，
`git reset --hard` + 重建镜像得到的是「有页面没 JS」的残骸，线上所有 chunk 404
（r13 事故根因，构建日志全程绿色，极具欺骗性）。

改过前端后提交前自查：

```bash
git status app/dist                       # 必须能看到新增/变更的 .js chunk
git ls-files app/dist | wc -l             # 期望 757
git ls-files app/dist/_nuxt | grep -c '\.js$'   # 期望 142
git check-ignore -v app/dist/index.html   # 无输出才算没被忽略
```

看不到 js 就用 `git check-ignore -v <文件>` 定位是哪条规则拦的。
**dist 只能用源码重建**（`cd app && bash build.sh`），不要拿旧包里的 dist 顶替——
旧 dist 虽自洽但缺新页面，会出现「升级入口 / 友情链接 / 作者归一页消失」这类假 bug。

### 10. 新增「要持久化的设置」必须进 PERSISTABLE_KEYS —— 而且两套白名单都要看

`SettingsSaver.dumpfile()` 是**整份覆盖** `auto.py`：`args` 里没有的键，文件里就不再有。

两套白名单分工不同，别只看一套：

| 白名单 | 管什么 |
| --- | --- |
| `ADMIN_SETTING_KEYS` | 设置页 POST **接受**哪些键（前端提交后要过这一层过滤） |
| `PERSISTABLE_KEYS` | `dumpfile()` 时哪些键**值得写回** `auto.py` |

`AdminSettings.post` 会 `clear()` 后只填前端提交的键，所以**「只在 PERSISTABLE、不在
ADMIN」的键每次保存都会被抹掉**（读者组 `READER_GROUPS` 连续丢两次的根因，r16 修）。
这类键由各自的服务用 `save_partial()` 写入，必须靠 `save_extra_settings()` 入口的补键逻辑兜住。

新增设置项时：两套白名单都要判断该进哪个 → `tests/test_setting_saver.py` 里
`TestSaveExtraSettingsCarryOver` 有现成用例（模拟「只提交一个无关键」的 POST 路径）
→ 反向验证（临时删掉补键逻辑，测试必须变红，否则断言是假的）。

### 11. `scripts/pack.sh` 必须用 bash 跑

脚本用了 `set -o pipefail`（bash 专有），shebang 早已改为 `#!/usr/bin/env bash`。
用 `sh scripts/pack.sh` 跑会在第 4 步验包时报 `Illegal option -o pipefail` 并中断，
md5 也打不出来。统一用 `bash scripts/pack.sh`。

### 12. 改完先想「要不要重建镜像」：小改动用 `hot-update.sh` 就够

NAS 上 `docker compose up -d --build` 即使全命中缓存也要几十秒起。判断口径：

| 改动 | 上线方式 |
|---|---|
| `app/src`（已 `bash app/build.sh` 出 dist） | `sh scripts/hot-update.sh --no-restart` |
| `webserver/**/*.py` | `sh scripts/hot-update.sh`（覆盖 + 预检 + 重启 tornado） |
| Dockerfile / requirements / 系统包 / `conf/` / `myreader-dist` | 必须 `up -d --build` |

两个注意点：
- 热更改的是容器可写层，**重建镜像会被覆盖回镜像内版本**，源码必须照常提交；
- 前端热更用 tar 管道，别用 `docker cp src/. dst/`（`dist/avatar` 是软链，合并语义撞类型冲突，详见 MEMORY.md ②）。

### 13. 分类图标是「按名字猜」的，改规则要同步改测试

`webserver/base/category_icons.py` 的 `_RULES` **顺序敏感**：先命中的生效。
往表里加规则时，注意别让宽泛词（`小说`、`书`）挡在具体词（`科幻`、`科幻小说`）前面。
`tests/test_category_icons.py` 锁了「演播:某人 → 电台图标」「科幻小说 → 火箭」这类优先级，
改规则后跑一遍：`python3 -m pytest tests/test_category_icons.py -q`。

### 14. 列表拖拽排序：key 不能拿下标，数据也不能整份替换

设置页的友情链接用 `vuedraggable`（`app/src/pages/admin/settings.vue`）做拖动排序，三个坑连着踩：

1. **`v-for` 的 key 不能用下标**。Sortable 是先移动真实 DOM、再由 Vue 重排 vdom；key 是下标时
   Vue 按位置复用元素，输入框里正在编辑的文字会「跟着」跑到别的行。要给每条挂一个稳定 id。
2. **这个 id 不能进配置文件**。用 `Object.defineProperty(item, "_uid", { value, enumerable: false })`
   挂成非枚举属性：`Object.assign` / `JSON.stringify` / `Object.keys` 都看不见它，
   保存时不会写进 `auto.py`，也不影响「未保存修改」的 JSON 比对。
3. **不要把数组整体替换**。`:list="settings.FRIENDS"` 绑的是数组引用，`moveFriend` 早期用
   `slice` + `$set` 换新数组（为了绕开「Vue 2 侦测不到下标赋值」），结果拖拽组件还指着旧数组。
   用 `splice` 摘出再插入：既触发响应式，又保住同一个引用。

验证方式：`drag_to()` 在无头 Chromium 里能跑通（`handle` 限定把手、`delayOnTouchOnly` 不影响鼠标），
拖完比对「数据顺序 / `_uid` / 输入框内容」三者是否一一对应。

### 15. 「顺手修脏数据」经常是删掉唯一的线索

`reader_group` 在用户归属里只存**组名字符串**（`Reader.extra["reader_group"]`），组定义存在
`CONF["READER_GROUPS"]`。两边不同步时就是「悬空引用」：用户被判定为「组不存在 → 读不到任何书」，
界面上却看不到这些人。

最早的处理是「发现悬空就清掉引用」，看起来是在修数据，实际很糟：

- 清掉之后**不可逆**，组定义一旦重建，人也回不来了（DB 里没有 `extra` 的历史）；
- 它在**列表接口**里执行，管理员还没看到告警，线索已经没了；
- 悬空本身并不危险——`effective_limits()` 对 `group-missing` 一律按「读不到书」兜底。

现在只统计（`orphan_groups()`）不清除，另给一个显式的幂等重建接口
（`POST /api/admin/reader_groups/revive`，`names` 缺省 = 全部），重建出的组是
**白名单 + 空条件**：人先归位，规则留空仍是「读不到书」，不会在管理员配好之前放行全库。

判断标准：清理动作如果会丢掉「无法从别处重算」的信息，就别放在读路径上，改成显式操作 + 可回滚。

### 16. Gitee raw 有内容审核：代码里别写露骨/暴力词组（否则整份文件 451）

`gitee.com/<owner>/<repo>/raw/<branch>/<path>` **不是纯静态文件服务**，它过内容审核。
一旦被判违规，返回 `451 The content may contain violation information`，于是：

- `git clone` / `git fetch` 正常（走 git 协议，不审内容）→ 本地看起来"代码好好的"；
- 在线更新（`_raw_url()` 直链下载）必然失败 → 下到那个文件就断，谁装谁失败。

r18 就这么废掉一版：读者组「家庭共用」模板写了几个露骨标签词，整份
`webserver/services/reader_group.py` 被判违规。实测结论（临时分支逐词探测）：
「血腥暴力」连排触发，写成 `血腥,暴力` 不触发；`情色`/`色情`/`性爱` 单独出现不触发，
但叠在整段里就整份被判。**别指望穷举词表**，按规矩来：

- 会被 raw 下载的文件（`webserver/**`、`app/dist/**`）里不写露骨/暴力/涉政词组；
- 需要这类语料时用中性词（如「成人向」「惊悚」），并让管理员从本库真实标签里自己补；
- **发布前跑一遍全量下载自检**：把清单里每个文件用 `MyBooks-VersionCheck/1.0` 的 UA
  下载并核对 sha256，全部 200 再打 tag。r18 就是漏了这一步。

配套的失败提示也改了：`_get()` 对 4xx（除 408/429）不再重试（原来空等 90 秒），
`_download_failure()` 把路径和「这是发布侧问题、与本机网络无关、可整包部署」写进错误里，
`handlers/version.py` 返回 `{err, msg}` 而不是把 traceback 抛给页面。

### 17. 「永不 settle 的 Promise」= 无限转圈且零提示

服务启动期（含在线更新后重启、数据库升级）端口由一个临时服务占着，它把**所有**
`/api/*` 回成 `{"err": "server_starting"}`（`webserver/startup_status.py`）。
`$backend` 为了「启动期间不弹一堆错误框」，对这种响应直接 `return new Promise(() => {})`
——一个**永不 resolve 的 Promise**。

问题在于：如果请求是在**导航结束之后**发出的（mounted 里补拉数据、展开某个面板、
点「重试」），`app.context.redirect()` 已经是空操作，页面不会跳走；于是调用方的
`await` 永远挂在那里，`loading=true` 永不结束 —— 用户看到的就是「一直转圈，
不报错、不提示、刷新才恢复」。

> ⚠️ **归因更正**：r20 曾把「读者组面板一直转圈」记成本节的坑，**这是错的**。
> 读者组的真因是模板带参调用 computed 方法（踩坑 #18），接口一直是 200。
> 本节描述的坑真实存在（启动期请求确实会挂住），但不要再拿它解释读者组转圈。

规矩：

1. 用 `new Promise(() => {})` 表达「本响应无须回调」时，**必须同时给出可见的出路**。
   `$backend` 现在与 502 分支一致：300ms 后整页 `window.location.assign("/starting?next=…")`。
2. 任何会显示 spinner 的 `await`，都应带超时兜底（`Promise.race` + 定时器），
   超时后停掉转圈、显式报错并给「重试」入口，而不是让用户干等。
   参考 `ReaderGroupEditor.vue` 的 `reload()`。
3. 排查这类「转圈」时，**先看 Console，再看 Network**：Console 里有
   `TypeError` 说明渲染早期就死了（见 #18），此时 Network 里请求多半是好的；
   Network 里 **pending 且无响应** 才多半是服务在启动/重启，`200` 且返回
   `server_starting` 就是本节的坑。

### 18. 方法误入 `computed`：接口 200、数据正常，页面照旧转圈

真实事故：`ReaderGroupEditor.vue` 把 `modeText(mode)` 写进了 `computed`，
模板却是 `{{ modeText(groups[name].mode) }}`。表现是**读者组列表与「分组权限」下拉
双双不出现，页面永远停在 spinner**，而接口 `200`、正文 548 B、两组数据完整。

**机理**（Vue 2）：

1. computed 的成员是**无参属性**：`modeText` 被求值一次 → 得到一个**字符串**；
2. 模板对字符串加括号 → `TypeError: e.modeText is not a function`；
3. 异常抛在 `_render` 里，patch 中断 → DOM 保留**上一次成功渲染的结果**（初始 spinner）；
4. `reload()` 里 `loaded = true` / `loading = false` 其实都执行了，但已无法重绘。

所以这是三个「看起来对」叠出来的假象：

| 你看到的 | 你以为 | 实际 |
| --- | --- | --- |
| 一直转圈 | 请求没回来 | 请求早回来了，DOM 冻住了 |
| 加了超时也没用 | 等得比超时还久 | 超时跑了、状态改了，没有渲染出口 |
| 保存能用 | 组件整体正常 | 保存不走这条渲染分支 |

**检测方式**：

- 浏览器 Console 一定有一条 `TypeError: … is not a function`，栈里带 chunk 名 + 列号；
  用列号回查压缩产物里 `xxx(` 的出现位置，能和源码调用点对上；
- 压缩产物里看 `computed:{` 与 `methods:{` 的偏移：方法定义落在 `computed` 区间即错；
- 仓库里用契约测试锁住：`tests/test_reader_group_frontend_contract.py`
  解析 `<template>` 段，把 `computed` 的键逐个匹配 `键(`，命中即失败。

**规矩**：

1. 模板里**带参调用**的东西只能放 `methods`；`computed` 只放无参派生值。
2. 从「内联三元」抽成方法时，先想清楚抽出来的是**方法**还是**计算属性**——
   这次就是抽对了方法、放错了位置。
3. 组件里任何 `await` 之后的状态更新都假设「会重绘」是危险的；有异常兜底
   （`errorCaptured` / 全局 `errorHandler`）时至少要把错误显示出来，别只剩 spinner。

完整复盘见 `docs/故障复盘-读者组转圈.md`。

### 19. 重编前端会丢 `app/dist` 里的非构建资源

`nuxt generate` **先清空 `dist/`** 再生成。而 `app/dist` 里除了 `_nuxt` 构建产物，
还有一批手工放入、**不是构建出来的**资源：

| 目录 / 文件 | 作用 | 数量 |
| --- | --- | --- |
| `static/pdfjs/**` | PDF 阅读器（`settings.py` 的 `PDF_VIEWER` 指向 `web/viewer.html`） | 369 |
| `static/fonts/*`（Poppins） | 字体 | 3 |
| `static/wallpaper/*` | 壁纸 | 4 |
| `static/images/*` | 图片 | 4 |
| `static/js/jquery-1.11.1.min.js` | jQuery | 1 |
| `static/toolbox-bridge.js` | 工具箱桥接 | 1 |
| `icons/*.svg` | 图标 | 11 |
| `robots.txt`、`static/README` 等 | 杂项 | 3 |

事故实例：r20 的 dist 有 **757** 个文件；按「构建产物 348 + logo/avatar 14 = 362」
口径重编后只剩 **362**，漏掉 **395 个真实文件（15,346,411 B，gzip 4,994,974 B）**。
当时这**不会让构建失败**（Dockerfile 只强依赖 `dist/logo`、`dist/avatar`），线上表现是
**PDF 入口 404、字体/壁纸/图标静默 404、工具链断**；r24 之后 builder 末尾已加硬门禁，缺 pdfjs 直接失败。

**规矩**：

1. 这类资源放 `public/`（`nuxt.config.js` 的 `dir.static = '../public'`），
   `generate` 会自动带出；`app/dist` 里的副本只用于兼容历史产物。
2. **前端重编后必须整目录校验 dist，不能只数构建产物。**
   一条命令：`sh scripts/check-dist.sh`（关键路径 + 各目录数量下限 + 总数必须 = 757）；
   `scripts/pack.sh` 出包前会自动调它，`--check` 验包时再查一次。
3. `Dockerfile` builder 末尾有硬门禁：`/app-static/dist/static/pdfjs/web/viewer.html`
   不存在就打印原因并 `exit 1`——宁可构建失败，也不要出「装得上但缺文件」的镜像。
4. 清理旧 chunk 用**白名单差集**（`comm -23`：当前 dist 的文件名减去上一份干净包的文件名），
   不要用 `grep` 扫引用。排除 `_nuxt` 后再扫，很容易把运行时动态加载的
   **Vue 运行时 `84f214b.js`**、**语言包 `76d48a7.js`** 误判成孤儿。
   本次 59 个旧 chunk 虽引用数为 0，也只能用差集确认。
   已知现象：`rsync` 同步 dist 到构建上下文时若不加 `--delete`，镜像里会累积残留
   （实测 824 = 757 + 67），功能不受影响，但会让「整目录校验」失效。
5. 打包清单里记 `dist_files`，与基线不一致就停下来复核，不要「数字自洽」地放过。

### 20. 预渲染壳页把 `asyncData` 当唯一取数入口 → 首屏永久空白

`nuxt generate --spa`（`target: 'static'`）会在**构建期**对每条路由跑一次 `asyncData`，
把结果序列化进 `window.__NUXT__.data`；运行期只 hydrate，**`asyncData` 不会再执行**。
如果页面又只在 `beforeRouteUpdate` 里重取，那两种进入方式的表现完全不同：

| 进入方式 | `asyncData` | `beforeRouteUpdate` | 结果 |
| --- | --- | --- | --- |
| 构建期预渲染 | 执行一次 | 不触发 | 产物里是当时的快照（常为 `data:[{}]` 空壳） |
| 首屏直接打开 / 强刷 | **不执行** | **不触发**（没有「上一个路由」） | 零请求，永久空白 |
| 从侧栏其它页点进 | 不执行 | 同组件复用才触发 | 正常出数据 |

**规矩**：

1. 首屏取数入口必须落在一个运行时生命周期里（`created` / `mounted`），
   `asyncData` 只能作为构建期首屏加速，**不能是唯一入口**。
2. 用 `ssr_loaded` 标记去重：`asyncData` 只有在 `rsp.err === 'ok'` 时置 `true`；
   `mounted` 里 `if (!this.ssr_loaded && !this.inited) this.init(this.$route)`，
   再叠加请求令牌（旧响应不覆盖新页面），保证「首屏必取一次、切路由/翻页不重复」。
3. `beforeRouteUpdate` 只覆盖「同组件 params/query 变化」，别把它当跨页导航的兜底。
4. 这类缺陷在 Console 里**没有报错**（压根没发请求），只能靠 Network 里「无取书请求」判定；
   排查时先看有无请求，再谈接口和缓存。
5. 同类形态已纳入静态检查：`npm run lint:refs -- --strict` 会扫「有 `asyncData` 但无生命周期取数」
   和「只在 `$route` watch 取数且缺 `immediate`」两种写法（68 个自有页面，0 处隐患）。

完整复盘见 `docs/故障复盘-所有书籍首屏空白.md`。

### 21. `this.alert` 不存在：报错被 Promise 吞掉，界面只剩空白

Vue 插件用 `inject('alert', ...)` 暴露的是 **`this.$alert`**。写 `this.alert(...)` 得到
`undefined is not a function` 的 `TypeError`；如果它发生在 `$backend().then(...)` 的回调里，
异常会变成 rejected Promise 而被吞，**数据停在初始空数组、弹窗也不出现**，
现场表现是「壳都在、网格空、Console 干净」——和「接口返回空」几乎无法区分。

**规矩**：

1. 插件/注入成员一律带 `$` 前缀（`$alert`、`$backend`、`$nuxt`），不要凭记忆写。
2. 错误分支必须同时做两件事：**弹窗** + **渲染可见的错误态**（`load_error` / `errorText` / 重试按钮）。
   只有弹窗时，一旦弹窗本身抛错就彻底静默。
3. 任何 `await` / `then` 回调里的 UI 调用都要假设可能抛错；catch 里不要再调用可能不存在的成员。
4. 静态检查兜底：`npm run lint:refs`（`app/scripts/check-vue-method-refs.js`）比对
   `this.NAME()` 是否真实存在于 methods/computed/data/props/inject/运行时赋值，`--strict` 即失败；
   对应的契约测试在 `tests/test_frontend_silent_failures.py`（禁止 `this.alert(`）。

### 22. 前端页大小不封顶 vs 服务端 `MAX_PAGE_SIZE`：第二页必空

后端列表接口有 `MAX_PAGE_SIZE`（当前 200，LITE 模式 60），超出会被截断；
前端若把用户选择的页大小（如 500）原样拼进 `start`/`limit`，就会出现
**「总页数按 500 算、实际每页只回 200 条」**，第二页的 `start` 直接越过总数 → 空列表。

**规矩**：

1. 页大小统一走 `app/src/utils/pageSize.js` 的 `clampPageSize(value, fallback, max=200)`，
   与后端常量保持一致（LITE 60），不要在页面里各写各的。
2. 服务端截断 `total` / `items` 时要保证两者口径一致（r26 同时修了 `ids` 分支
   扣除隐藏独享书后 `total` 与可见集合不符的问题）。
3. 改动分页参数后至少验证：第 1 页、最后一页、页大小大于服务端上限这三种情况。
