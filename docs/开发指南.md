## 一、技术栈与架构总览

```
┌────────────────────────────────────────────────────┐
│  浏览器 / MyReader / OPDS / WAP / 移动 App          │
└────────────────────┬───────────────────────────────┘
                     │ nginx (反代 + 静态 + 444 屏蔽)
┌────────────────────▼───────────────────────────────┐
│  Tornado (webserver/main.py)                       │
│  ├── handlers/    ← 路由 + 请求处理                 │
│  ├── services/    ← 业务逻辑 + 后台任务              │
│  ├── plugins/meta/← 信息源插件（刮削）               │
│  ├── toolbox/     ← 工具箱工具                      │
│  ├── worker/      ← epub→audio 转换 worker           │
│  └── base/        ← BaseHandler + 公用基础设施       │
├────────────────────────────────────────────────────┤
│  Calibre LibraryDatabase (metadata.db)              │
│  + SQLite (calibre-webserver.db: 用户/权限/进度等)   │
├────────────────────────────────────────────────────┤
│  Vue 2 SPA (app/dist/, 预构建进包)                   │
│  MyReader (myreader-dist/, Next.js standalone)      │
└────────────────────────────────────────────────────┘
```

**一句话**：Tornado 单进程事件循环，Calibre 管书库数据，SQLite 管用户数据；
前端 Vue 2 预构建进包不走 NAS 构建；MyReader 是内嵌的 Next.js 阅读器。

## 二、代码导航（改一个功能要碰哪些文件）

| 要改什么 | 核心文件 | 备注 |
|---|---|---|
| 页面路由 / API | `webserver/handlers/*.py` | 每个模块一个文件，末尾 `routes()` 函数注册 |
| 业务逻辑 | `webserver/services/*.py` | AsyncService 子类或独立类 |
| 信息源插件 | `webserver/plugins/meta/*/plugin.py` | 见下文「新增信息源插件」 |
| 工具箱工具 | `webserver/toolbox/*_tool.py` + `app/src/pages/toolbox/*.vue` | 见 `document/toolbox_design.md` |
| 有声书播放 | `app/src/pages/audio/_id.vue` | 播放器 + 进度 + 字幕，1800+ 行 |
| 有声书转换 | `webserver/worker/epub2audio_worker.py` + `webserver/epub_to_audio/` | subprocess 调 edge-tts |
| 设置项 | `webserver/settings.py`（默认值）+ `webserver/base/setting_saver.py`（白名单）+ `app/src/pages/admin/settings.vue`（UI） | 三处必须同步 |
| 版本号 | `webserver/version.py` + 6 个载体 | 用 `--set` 一条命令，见下文 |
| 备份 | `scripts/backup.sh` + `scripts/backup_run.py` | |
| 检索索引 | `webserver/services/search_index.py` | FTS5，独立 .db |
| 听书进度 | `webserver/handlers/audio.py` AudioPlaybackProgress + `models.py` AudioPlayback | |

### settings.vue 的 groups 配置

设置页是数据驱动的：`this.groups` 数组定义分组/节/字段/嵌套组/special 块。
改设置 UI 只动这个数组 + locale + 搜索别名表（`al` 字段），保存/脏跟踪自动适配。

**已归堆（build.27-r11）**：`users-access`（访问控制与读者组）、`users-reg`（注册、邀请与新用户）。
不再有单独的 users-guest / users-default / reader-groups 卡。

## 三、数据库

### calibre metadata.db（书库）

| 表 | 用途 | 注意 |
|---|---|---|
| `books` | 书目主表 | **没有** `publisher` / `series` 列（见踩坑 #1） |
| `books_authors_link` + `authors` | 作者（多对多） | |
| `books_tags_link` + `tags` | 标签（多对多） | |
| `books_publishers_link` + `publishers` | 出版社（多对多） | |
| `books_series_link` + `series` | 丛书（多对多） | |
| `comments` | 简介 | 正常一书一条，但老库可能多行——JOIN 后聚合去重 |
| `custom_columns` | 自定义列（`#narrator` 等） | 由 calibre API 管理 |

### calibre-webserver.db（应用数据）

| 表 | 用途 |
|---|---|
| `readers` | 用户（`extra` JSON 存读者组归属） |
| `readings` / `book_reading_stats` | 阅读进度与统计 |
| `audio_playback` | 有声书播放进度（跨设备续播） |
| `scanfiles` | 扫描导入记录（`hash` 防重、`audiodir:` 标记） |
| `biz_key` | 下载 / 合集导出的临时密钥 |
| `messages` | 站内消息 |
| `koreader_position` | KOReader 阅读位置同步 |

### 启动时自动建的表

`models.py` 的 `_NEW_TABLES_AUTO_ENSURE` 元组列出的表随启动 `create_all(checkfirst=True)` 幂等创建。
新增表时加进这个元组即可，不需要用户手动 `--syncdb`。

## 四、常见开发任务

### 4.1 新增一个信息源插件

1. `webserver/plugins/meta/<name>/` 新建目录：`__init__.py`（re-export）+ `plugin.py` + `api.py`
2. `plugin.py` 继承 `MetaSourcePlugin`，实现 `search(title, isbn, publisher)` 和可选 `search_best(mi)`
3. `SOURCE_KEYS = (META_SOURCE_XXX,)`，`PROVIDER_KEY = KEY`
4. `webserver/services/book_search.py` 的 `_PLUGIN_CLASSES` 加上插件类
5. `webserver/constants.py` 加 `META_SOURCE_XXX = "xxx"`
6. 设置页 `settings.vue` 的 `meta_sources` 多选自动出现（来源走 `all_sources()`）
7. `webserver/settings.py` 加默认源列表（`META_SELECTED_SOURCES`）和限流键
8. 三语 locale 补标签

⚠️ **calibre schema**：查 metadata.db 时出版社/丛书走链接表（见踩坑 #1），不要假设 books 表有这些列。

### 4.2 新增一个 handler 路由

1. `webserver/handlers/<module>.py` 新建类继承 `BaseHandler`
2. 用 `@js` 装饰器（统一 JSON 输出 + CORS + 异常处理）、`@auth` / `@is_admin` 做鉴权
3. 末尾 `routes()` 返回 `(r"/api/...", HandlerClass)` 列表
4. `webserver/main.py` 的 `names` 列表加模块名（如果新建了 .py 文件）

### 4.3 新增一个工具箱工具

见 [`document/toolbox_design.md`](../document/toolbox_design.md)。概要：

1. `webserver/toolbox/<name>_tool.py` 继承 `ToolBase`，声明 `tool_id` / `name`
2. `webserver/toolbox/toolset.py` 注册
3. `app/src/pages/toolbox/<name>.vue` 前端页面
4. `webserver/handlers/toolbox.py` 或独立 handler 暴露 API

### 4.4 新增设置项

1. `webserver/settings.py` 加默认值
2. `webserver/base/setting_saver.py` 的 `ADMIN_SETTING_KEYS` 加键名（不加则保存被静默丢弃）
3. `app/src/pages/admin/settings.vue` 的 `groups` 配置加字段定义
4. 三语 locale 补 label / tips
5. 需要重启才生效的键加进 `RESTART_REQUIRED_KEYS`

### 4.5 版本升号

```sh
python scripts/check-version-lock.py --set 4.6.0-build.<N>
```

一条命令改全部九处载体（version.py / compose / Dockerfile / package.json /
package-lock / Makefile / 校验器常量 / README 示例 / tests 字面量），改完自动复检。
CHANGELOG 版本条目**人工写**（pack.sh 从首条标题取号）。

### 4.6 发布一个修订

```sh
# 1. 改代码 → py_compile → 更新 CHANGELOG
# 2. 提交推送
git add -A && git commit && git push
# 3. 出清单（纯后端 .py 改动 → requires_dist=false 可页内热更）
python3 scripts/gen-update-manifest.py \
  --revision 4.6.0-build.27-r13 --base-revision 4.6.0-build.27-r12 \
  --base-commit 6cb18b0 --summary "..." --notes "..."
# 4. 提交推送 manifest
# 5. NAS 上点「立即更新」（纯后端）或整包部署（含前端/镜像级）
```

## 五、关键设计决策与原因

### 版本检测与在线更新

`update/manifest.json` 是唯一发布源（Gitee raw 直链），按修订号 `-rN` 比对。
纯后端 `.py` 改动可页内热更（下载→sha256 校验→原子替换→自动重启）；
含前端产物必须重新部署。详见 [`docs/在线更新说明.md`](在线更新说明.md)。

### 有声书音频跟着书目录走

音频放 `library/<作者>/<书名> (id)/.audio/`，与电子书同目录。
旧布局 `audios/<id>/` 已废弃（4.6.0-13 起），`upgrade.sh` 自动迁移。

### 播放进度三层

| 层 | 存储 | 范围 |
|---|---|---|
| localStorage | 浏览器本地 | 同浏览器关了再开能恢复 |
| 服务端 `audio_playback` | 数据库 | 跨设备续播 |
| KOReader 同步 | koreader_position | 电子书阅读位置（有声书未接入） |

前端 `tryRestoreFromServer()` 做「谁新用谁」仲裁（`client_ts` 时间戳）。

### 读者组三层权限

```
REQUIRE_LOGIN（门槛：谁能进）
  └→ ALLOW_READ_RANGE_SETTING（总开关：是否启用阅读范围控制）
       └→ READER_GROUPS_ENABLED（读者组开关：组规则是否生效）
            └→ 用户自身 read_limit / limit_tags（个人设置，优先于组）
```

## 六、踩坑清单（每次都看，血泪教训）

### 1. calibre books 表没有 publisher / series 列

出版社/丛书走 `books_publishers_link` / `books_series_link` 链接表。
直接写 `b.publisher` / `b.series` 真库必炸 `no such column`（build.27-r12 修复）。

### 2. FTS5 重复 rowid = constraint failed

FTS5 虚拟表 INSERT 时 rowid 已存在会报错（不是 REPLACE）。
JOIN 产生多行的场景（多评论/多链接）必须先聚合去重。

### 3. CRLF：Windows 工作区 ≠ git 仓库 ≠ Gitee raw

Windows 检出是 CRLF，git 仓库 / Gitee raw 是 LF（`.gitattributes` 强制）。
任何按工作区文件计算哈希/行数/字符串匹配的代码，在真库上都会出错。

已出过的事故：
- version.py CRLF → `check-version.sh` 五版本号比较全部「假 FAIL」（build.26）
- `check-version-lock.py --set` 写 version.py 为 CRLF（根因，build.26 断源修复）
- 清单哈希按工作区 CRLF 计算 → NAS 热更 sha256 必失败（build.27-r12）

**规则**：读文件用 `newline=""`（不转义），写文件用 `newline="\n"`（强制 LF），
哈希 / 字节比对 / 正则匹配统一按 **git blob**（`git show HEAD:<path>`）而不是磁盘文件。

### 4. myreader-dist 的 119 根符号链接

Next.js standalone 产物靠三层符号链接解析依赖。Windows 检出 / GUI 解压会压扁。
`deploy.sh` / `upgrade.sh` 构建前自动按清单校验并重建（`check-myreader-links.sh --fix`）。
**从 Windows 直接打包会压扁**——出包必须在 Linux/NAS 上跑 `pack.sh`。

### 5. Tornado 事件循环不能阻塞

handler 里同步做网络请求 / 大文件 IO / subprocess / time.sleep 会冻住全站。
阻塞操作丢进 `utils.run_in_threadpool` 或 `run_in_executor`。
`@js` 装饰器支持 `async def`，Tornado handler 原生支持协程。

已修的现场：ffprobe 200 次（build.21）、EPUB 整本读写（build.21）、
save_book_meta（build.21）、zip 打包（build.27-r12）。

### 6. 并发写 SQLite 必须走队列或锁

calibre 写 `metadata.db` 是单写者模型，多线程并发导入会让事务互等。
Phase2 攒批 + 短写事务 + worker 单线程是正确设计，不要改成多 worker。

### 7. 响应式数据不要放 Audio / Media 元素

Vue 2 把 Audio 元素上的事件回调做成响应式依赖后，任何 timeupdate 都会触发
整棵子树重新求值——表现为进度条被按住不动、状态灯疯狂闪烁。
播放器实例挂 `this._el`（非响应式），回调只做纯赋值。

### 8. douban-rs-api 伴生容器

豆瓣 v1 信息源需要一个 sidecar 容器（`douban-api-rs`），单容器/vDSM 部署
通常没有。未配置 `douban_baseurl` 时插件跳过（build.27-r12 起）。
douban_v2 直连 book.douban.com 不需要容器，是实际在用的豆瓣源。

### 9. `app/dist` 必须完整入库：`.gitignore` 里的 dist 规则已删

`app/.gitignore` 曾带两条模板规则（Node 模板 `/dist` + Nuxt 模板 `dist`），
把 `app/dist/_nuxt/*.js` 全挡在仓库外。仓库里只剩 html/css/fonts，
`git reset --hard` + 重建镜像得到的是「有页面没 JS」的残骸，线上所有 chunk 404
（r13 事故根因，构建日志全程绿色，极具欺骗性）。

改过前端后提交前自查：

```bash
git status app/dist                       # 必须能看到新增/变更的 .js chunk
git ls-files app/dist | wc -l             # 期望 757
git ls-files app/dist/_nuxt | grep -c '\.js$'   # 期望 142
git check-ignore -v app/dist/index.html   # 无输出才算没被忽略
```

看不到 js 就用 `git check-ignore -v <文件>` 定位是哪条规则拦的。
**dist 只能用源码重建**（`cd app && bash build.sh`），不要拿旧包里的 dist 顶替——
旧 dist 虽自洽但缺新页面，会出现「升级入口 / 友情链接 / 作者归一页消失」这类假 bug。

### 10. 新增「要持久化的设置」必须进 PERSISTABLE_KEYS

`SettingsSaver.dumpfile()` 是**整份覆盖** `auto.py`，只写 `PERSISTABLE_KEYS` 白名单内的键。
漏了白名单，设置页任意一次无关保存都会把它静默删除（读者组分组规则就这样每次重建后全丢）。
新增设置项时：加白名单 → `tests/test_setting_saver.py` 加「键在白名单 + 保存后值不变」两条断言
→ 反向验证（临时删白名单，测试必须变红）。

### 11. `scripts/pack.sh` 必须用 bash 跑

脚本用了 `set -o pipefail`（bash 专有），shebang 早已改为 `#!/usr/bin/env bash`。
用 `sh scripts/pack.sh` 跑会在第 4 步验包时报 `Illegal option -o pipefail` 并中断，
md5 也打不出来。统一用 `bash scripts/pack.sh`。

### 12. 改完先想「要不要重建镜像」：小改动用 `hot-update.sh` 就够

NAS 上 `docker compose up -d --build` 即使全命中缓存也要几十秒起。判断口径：

| 改动 | 上线方式 |
|---|---|
| `app/src`（已 `bash app/build.sh` 出 dist） | `sh scripts/hot-update.sh --no-restart` |
| `webserver/**/*.py` | `sh scripts/hot-update.sh`（覆盖 + 预检 + 重启 tornado） |
| Dockerfile / requirements / 系统包 / `conf/` / `myreader-dist` | 必须 `up -d --build` |

两个注意点：
- 热更改的是容器可写层，**重建镜像会被覆盖回镜像内版本**，源码必须照常提交；
- 前端热更用 tar 管道，别用 `docker cp src/. dst/`（`dist/avatar` 是软链，合并语义撞类型冲突，详见 MEMORY.md ②）。

### 13. 分类图标是「按名字猜」的，改规则要同步改测试

`webserver/base/category_icons.py` 的 `_RULES` **顺序敏感**：先命中的生效。
往表里加规则时，注意别让宽泛词（`小说`、`书`）挡在具体词（`科幻`、`科幻小说`）前面。
`tests/test_category_icons.py` 锁了「演播:某人 → 电台图标」「科幻小说 → 火箭」这类优先级，
改规则后跑一遍：`python3 -m pytest tests/test_category_icons.py -q`。

### 14. 列表拖拽排序：key 不能拿下标，数据也不能整份替换

设置页的友情链接用 `vuedraggable`（`app/src/pages/admin/settings.vue`）做拖动排序，三个坑连着踩：

1. **`v-for` 的 key 不能用下标**。Sortable 是先移动真实 DOM、再由 Vue 重排 vdom；key 是下标时
   Vue 按位置复用元素，输入框里正在编辑的文字会「跟着」跑到别的行。要给每条挂一个稳定 id。
2. **这个 id 不能进配置文件**。用 `Object.defineProperty(item, "_uid", { value, enumerable: false })`
   挂成非枚举属性：`Object.assign` / `JSON.stringify` / `Object.keys` 都看不见它，
   保存时不会写进 `auto.py`，也不影响「未保存修改」的 JSON 比对。
3. **不要把数组整体替换**。`:list="settings.FRIENDS"` 绑的是数组引用，`moveFriend` 早期用
   `slice` + `$set` 换新数组（为了绕开「Vue 2 侦测不到下标赋值」），结果拖拽组件还指着旧数组。
   用 `splice` 摘出再插入：既触发响应式，又保住同一个引用。

验证方式：`drag_to()` 在无头 Chromium 里能跑通（`handle` 限定把手、`delayOnTouchOnly` 不影响鼠标），
拖完比对「数据顺序 / `_uid` / 输入框内容」三者是否一一对应。

## 七、测试

```sh
# 本地（Windows）可跑的子集（不需要 calibre / pytest 全套）
python -m pytest tests/test_search_index.py -q          # 6 例
python -m pytest tests/test_backup_run.py -q             # 6 例
python -m pytest tests/test_version_lock.py -q           # 9 例
python -m pytest tests/test_audio_books_cache.py -q      # 3 例
python -m pytest tests/test_pagination.py -q             # 若干
python -m pytest tests/test_background_tasks.py -q       # 若干

# 容器内跑全量（含 calibre 依赖的集成用例）
docker exec audiobook-mybooks-1 python3 -m pytest /var/www/mybooks/tests/ -q
```

**夹具原则**：按真实上游 schema 建表，不要为了方便复刻一个错误的 schema——
那会把 bug 固化成「本地全绿、真库必炸」（search_index 的 publisher 列就是这么栽的）。

**竞态测试**：用 Event / 条件变量控制时序，不要依赖 GIL 调度运气——
同一测试在开发机绿、在 NAS 红是最难查的 bug 来源。
