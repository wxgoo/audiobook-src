- 4.6.0-build.26（2026-11-08）
  - **修「假 FAIL」**：`check-version.sh` 打印五个版本号一模一样却连报三行 `!!`。
    根因是 `webserver/version.py` 为 CRLF，`sed -n 's/^VERSION…="\(.*\)"/\1/p'`
    只替换到收尾引号，**行尾 `\r` 残留进变量**；`echo` 到终端时 `\r` 把光标拉回行首，
    肉眼看不出来，但 `pkg_version` 比另外三个多一个字节，比较必然不等。
    六处取值统一加 `| tr -d '\r'`（`check-version.sh`×4、`deploy.sh`、`upgrade.sh`×2，
    以及交付侧 `check-deployed-version.sh` / `fix-build-layer.sh` / `recover.sh`）。
  - **断源**：`scripts/check-version-lock.py --set` 原用 `Path.write_text()`，Windows 下按
    `os.linesep` 换行，**每次改版本号都把 version.py 写成 CRLF**——真凶在此。改用
    `open(..., newline="\n")`，`webserver/version.py` 亦归一为 LF。
  - **`recover.sh` 入包并修口径**：DSM 7.2 套件名是 `ContainerManager` 而非 `Docker`，
    重启按 `ContainerManager → Docker → synoservice → systemctl` 候选逐个试；`PROJ`
    支持从 `scripts/` 运行；兜底 `curl | grep` 补上冒号后的空格（原来会静默空输出）。
  - **`check-deployed-version.sh`、`fix-build-layer.sh` 一并入包**（`scripts/`），
    解压即用，不再依赖交付目录里的散放文件。
  - 新增上文「常见构建失败」一节（`layer does not exist` / 重启口径 / `compose up` 误拉镜像）。
  - **前端无改动**：`app/dist` 与 build.25 逐字节相同（738 文件 / 71 入口页，
