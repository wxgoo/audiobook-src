### ⚠️ 升级事故与急救（r11 首版装了报 500 的看这里）

**症状**：装完 r11，访问任何需要登录的页面都是 500 / 空白，日志里：

```
sqlite3.OperationalError: no such column: readers.birth_year
[SQL: SELECT readers.id AS readers_id, ..., readers.birth_year ... FROM readers]
```

**原因**（一句话）：r11 的数据库迁移**根本没执行**。代码里判「是否需要迁移」
用的是 `installed_version != VERSION`，但 `VERSION` 从 r9 到 r11 一直是
`v4.8.0` 没动过——r10 那次启动早已把它写成 `v4.8.0` 落盘，所以升到 r11
仍然「相等」，被判成「不是升级」，补列那一步整个跳过。而模型里已经要读
`birth_year`，于是每一次 `SELECT readers.*` 都炸。

> 顺带一个更隐蔽的：就算判定改对了，原来所有迁移步骤共用一个事务，
> 任意一步失败就 `rollback` 全部，会把已补好的列一起撤掉——看起来像
> 「改了没用」。本次已改成每步独立提交。

**两条路，任选**：

用包里的 `scripts/hotfix-r11-birth-year.sh`，它就是补一列 + 按 `age`
回填，幂等，重复跑安全：

# 路径不对就显式带上：

不需要手工干预。已经用 A 救过的也建议换成 B，否则下次出包模型再加列时

### `-r11`：年龄改存出生年份（顺带修一个升级期白屏）

你上一版提的那句「改存出生年份再重算」，做完了。

**为什么要改。** r10 存的是「填表那一刻的整数岁」，它不会自己长大：12 岁
注册的孩子三年后仍被判成 12 岁，本该自动解锁的书永远解锁不了；反过来，
卡在未成年人组的成年人也得管理员一个个手工改。改存出生年份后，年龄由
当前年份实时算出，分组限额自然随时间推进，不用每年维护。

**对使用者有什么变化。**
- 注册页「年龄」变成「出生年份」（四位数字，1900~今年）。填完立刻显示
  「按 2026 年计算，你今年 30 岁」，填错年份当场能发现。
- 后续年份一律拒收（填不出未来人），空着也提交不了。
- 管理员用户列表的「年龄」列同时显示年龄和出生年份，例如 `12 (2014)`；
  历史未填的仍显示黄色「未填」。
- 管理员「修改年龄」对话框回填的是出生年份，改了之后保存的也是出生年份。

**老库怎么迁移（自动，不用你操作）。**

启动时 `adjust_reader_table()` 做三步：
1. 补列 `birth_year INTEGER NOT NULL DEFAULT 0`；
2. 把 r10 里 `age > 0` 的用户换算 `birth_year = 当年 - age` 回填；
3. 老列 `age` **保留不删**（SQLite 删列代价大，留着还能兜住回滚）。

关键是第 2 步只在本轮新补列时执行。若每轮启动都按 `age` 重算，管理员手工
纠正过的出生年份会被旧值覆盖回去——这一点已写成测试钉死（`test_migration_
does_not_overwrite_admin_fix`）。

实际效果（已用真库跑过）：`age=12 → birth_year=2014`、`age=30 → 1996`、
`age=0`（未填）→ 保持 0 不猜。

**升级后会看到什么。** 老用户不会因为这次改动被挡在门外：`birth_year=0`
一律视为「未填」，跟 r10 的 `age=0` 行为一致。要补填的人由管理员在用户
列表里改。

**顺带修的白屏隐患（建议看一下）。** 原来 nginx 没有 `location /_nuxt/`，
发版后浏览器若还持有旧页面、去取已经被删掉的 chunk，会命中 SPA 兜底规则，
返回 **200 + text/html**（实测确认 content-type 是 text/html、正文是
`<!doctype html>`）。浏览器解析 JS 时报 `Unexpected token '<'`，页面直接
白屏，只能手动 Ctrl+F5。现在两处一起补：
- nginx 加 `location /_nuxt/ { try_files $uri =404; expires 30d; }`，
  缺失的 chunk 老实回 404，不再拿 HTML 冒充 JS；
- 前端加 `plugins/chunk-reload.js`：命中 chunk 加载失败时自动刷新一次，
  15 秒冷却避免刷新风暴。

> ⚠️ **本次要动 nginx 配置。** 如果你的部署是自己维护的
> `conf/nginx/mybooks.conf`（不是直接用包里那份），需要把
> `location /_nuxt/` 那段手工合过去。不合并也能跑，只是升级瞬间仍有白屏
> 概率（前端自动刷新能兜住大部分）。

**构建命令也修了一处。** 这版出包时我先用了 `nuxt generate`（默认会预渲染
每页 HTML），结果 `/admin/users` 落到「500 服务正在启动中」——预渲染出的
DOM 与运行时 hydrate 不匹配。改用 `nuxt generate --spa` 后正常。已把
`package.json` 的 `generate` 脚本改成带 `--spa`，并加了
`tests/test_dist_spa_shape.py` 钉住这条，防止再手滑。

### `-r9` 增补（r10）：密码强度 + 注册必填年龄

你补充的两条要求。

**1. 密码不能少于 6 位，且至少包含「大写 / 小写 / 数字 / 符号」中的两种。**

原来只查长度 6~20 和一个字符白名单，`123456`、`aaaaaa` 都能过，等于没有
强度。现在统一成一条规则，**五个入口全部走同一份判定**：用户自行注册、
管理员建号、用户自己改密码、管理员改密码。

前端会边输边提示（弱密码当场标红），后端再校验一次（不信任前端）。
新规则对**已存在的老密码不追溯**——只在下次改密码时生效，不会把现有用户
锁在门外。

**2. 注册必须填年龄，并明确提示不得虚报。**

年龄用于图书分级：管理员审核时按年龄分组设置可阅读范围（有些书不适合
某个年龄段）。所以注册表单加了年龄字段和一条确认勾选：

> 我确认所填年龄真实有效，如有虚报由本人承担相应后果（包括但不限于因
> 年龄不实接触到不适宜内容）

不填年龄或不勾选确认都提交不了。

配套改动：
- 用户表加 `age` 列，老库**启动时自动补列**（默认 0 = 未填），不强制
  老用户回填——否则一升级全员被挡在门外。
- 管理员用户列表加「年龄」列，未填的显示黄色「未填」标签，一眼能看出
  谁还没填。
- 管理员账号管理里加「修改年龄」，方便纠正填错的、补上历史用户的。
  管理员自己那行没有这一项（年龄属"设置类"，后端白名单同样拦）。

> 📌 **r11 已把上面的 `age` 列换成 `birth_year`。** 这一段的「年龄」现在
> 指「出生年份」，迁移逻辑见本文件开头 r11 那节。保留这段是因为密码规则
> 和「不得虚报」的要求是 r10 提的，改动说明仍需可查。

### `-r9`：弹窗与播放页的进度终于是一份了

你提的三件事一次做完。

**1. 弹窗的进度和顶部播放页的进度同步了。**

原来这是两条完全独立的记录：弹窗按「每章一条」存在 `audiobook_preview_*`，
播放页按「整本一条」存在 `audio_progress_*` 并上报服务端。你从弹窗切到
播放页，那边一条记录都没有，只能从头听 —— 就是你说的「两个单独的进度」。

现在弹窗把同一份进度写进播放页用的那条键、同时上报服务端，两边共用。

修的过程中发现**第二个断裂点**，这个才是关键：弹窗以前只在「关弹窗 /
暂停 / 切章 / 离开页面」时才保存，**播放中什么都不写**。而你的实际操作
是听几分钟、不关弹窗、直接点顶部「有声书」进播放页 —— 那一刻
localStorage 里还是空的。现在改成播放中每 5 秒落一次，切走时进度就在。

顺带把服务端也接上了：在弹窗里听的、在播放页听的、在另一台设备听的，
现在都能续上（复用 r8 那套带时间戳仲裁的上报，不会互相覆盖）。

实测：弹窗点第 2 章 → 5 秒时共享进度已写入 → 关弹窗时 15 秒 →
打开播放页直接续到第 2 章第 15 秒，不再从零开始。

**2. 被分组限制的用户，首页不再显示全库统计。**

以前「图书总数 / 作者数」这些不管有没有限制都照发。现在受限用户
（非管理员 + 所在读者组有阅读条数限制）拿不到这些数字，整个统计板块
直接不显示。接口层面就不下发，不是前端藏起来。

**3. 管理员不再被各种选项套着。**

管理员那一行现在只剩「修改密码」和「修改用户名」，阅读范围、下载配额、
评论限制、激活/停用这些限制类入口全部去掉；删除自己的入口也不再显示。
后端同时加了白名单：对其他管理员只接受用户名和密码两个字段，其余的
一律拒绝，不允许取消别人的管理员权限、也不允许删管理员账号。

另外你说「管理员还可以改用户名」「也可以改其他用户名」——现在任何用户
都可以改用户名（包括改别人的、改管理员的）。改的时候顺手补了个校验
漏洞：用户名的正则原来只校验开头，`a-b`、`a bc` 这种都能通过，现在堵上了。
改名不会导致掉线（会话是按用户 id 存的）；如果那个用户没自己设过昵称，
昵称会跟着用户名一起变。

菜单名字也从「用户管理」改成了「账号管理」，页面上加了一行说明。

### `-r8`：又挖出 4 个真 bug（都是「偶发、难复现」那一类）

这一版回你的问题「还有什么潜在问题、能深度优化的问题」。**除了下面 4 个
已修的，交接单第八节还列了 3 个待你拍板的和 7 个优化建议**，按性价比排好了。

1. **来回切集会写错播放位置。** 恢复位置的重试链最长跑 5 秒，旧代码只靠
   「集号变了就作废」判断。你在这 5 秒内上一集/下一集来回点，集号又变回来，
   守卫失效 → 上一轮的旧位置被写进新加载的音频。现在用「代数」作废
   （每次换集代数 +1，旧回调一律失效），比逐个清定时器可靠。
2. **离开页面时最后一段进度会丢。** 离开页面的那次上报是普通 fetch，
   SPA 内部跳转时浏览器会随页面卸载把它取消，服务端收不到 → 换设备续播
   偶尔「差最后几分钟」。改成 `keepalive` 请求，脱离页面生命周期。
3. **两台设备听同一本书会互相覆盖进度。** 后到达的请求不一定是最新进度
   （另一台停着不动也会心跳），会把新进度盖回旧值。现在客户端带
   `client_ts`，服务端只接受更新的写入，旧的一律丢弃。
   老版本前端不带这个字段时放行，不会造成升级后进度全丢。
   老数据库会在启动时自动补一列（幂等，不用手工执行 SQL）。
4. **拖完进度条后滑块不跟播放走了。** 旧代码在滑块 `mousedown` 时置
   「正在拖动」，`mouseup` 时复位；用键盘方向键或点轨道这两种操作不触发
   mousedown，标志就一直是 true → 进度条从此冻住。改用 `@start/@end`，
   并在松手后立刻回写一次时间（否则会看到滑块「弹回原处再跳过去」）。

还顺手统一了上一集/下一集的切换路径：不再 `$nextTick` 后裸调 `play()`
（换源瞬间 readyState 还是 0，play() 会被丢弃），改走和点列表一致的
「认播放意图 + 等 canplay」。

### `-r7`：消除「点一下转个圈才开始」

你反馈：弹窗卡死已好，但「退出再回来，点击播放转个圈就开始了」。

转圈来自**续播位置落地太晚**：旧实现等 `canplay` 才 seek——先从头开播、
播出声、再跳到上次听到的位置。播放中的 seek 会重新发起 Range 请求、
重新填缓冲，所以看到的就是「转个圈，然后才从中间开始」。

现在改为在 `loadedmetadata` 阶段直接定位（此时已拿到时长，还没开始播），
浏览器带着目标位置去取数据，一次到位。实测 `playing` 事件触发时时间
已经在 45.00 秒，全程只 seek 一次，没有二次缓冲。

还修了一个由此暴露的问题：原来的兜底 seek 依赖一个变量，改成直接赋值后
那个变量再没被写过，兜底实际已失效。现在 seek 成功时同步登记，
且只有「确实没落到位（偏差超过 2 秒）」才补，已生效就不动。

实测：有续播 45s → playing 时 t=45.00、seek 1 次；无续播 → t=0、seek 0 次。

### `-r6` 与本次同批：下方「有声书」恢复弹窗（r4/r5 把方向理解反了）

你两次说的「不是弹窗啊，还是跟顶部的一样」，意思一直是：

### `-r5`：看门狗从「固定 8 秒」改为「进展制」

r4 的看门狗按固定 8 秒计时——这个阈值确实不靠谱：网络盘上正常加载
一集可能就要 20 秒以上，固定倒计时会把「慢」误判成「死」，反复打断
正常加载，反而永远播不了。

现在只看「有没有进展」，有任意一种就不动手：

- 时间在走（正在播）
- readyState 在爬升
- buffered 在增长（监听 progress 事件，字节还在到就不算卡死）

连续 12 秒（6 个 2 秒周期）完全零进展才重拉；最多重拉 3 次，
仍无进展则停止重试并提示「第 N 集播放失败」，不会无限循环。

顺带修了一个自愈死锁：媒体错误事件里清播放意图的旧逻辑与看门狗
冲突（重拉后再失败 → 意图被清 → 看门狗停摆永不自愈），已改为由
重拉上限统一决定放弃时机。

Chromium 实测三种场景：

| 场景 | r4（8s 固定） | r5（进展制） |
|---|---|---|
| 慢速但持续来数据（每 8KB 停 1.2s，8s 开播） | 会被误杀 | 全程 0 重拉，正常开播 |
| 挂死 16s 后恢复 | 看运气 | 第 2 次重拉（+24s）自愈 |
| 永久挂死 | 8s 后反复重拉无限循环 | 12s/24s/34s 三次重拉后放弃并提示 |

`-r4` 的其余修复（详情页入口统一、dist 重建、togglePlay/续播等）全部包含，见下节。

### `-r4` 修的是「详情页有声书点了没反应」

你说「详情页下方的有声书不是弹窗啊，还是跟顶部的一样，这次修了个寂寞」——
**你是对的，上一次的修复根本没生效**，原因有两个，叠在一起：

**（1）前端产物没重建。** 上一版改动只进了 git 源码，`app/dist` 还是 11-04
15:17 的旧产物。`Dockerfile:16` 判定 `app/dist/index.html` 已存在就
**跳过 `npm ci` 和 `build-spa`**，直接拿包里的 dist 进镜像。于是源码改了、
包也打了，但镜像里跑的还是旧 JS。这次已重建（dist 时间 11-05 09:47），
并从 tar 包里解出来核对过：新逻辑确实在 `app/dist/_nuxt/` 里。

### 顺带根治的三处「播放器点不动」

这些是在真实 SPA 产物上用 Chromium 复现出来的，不是推测：

| 问题 | 根因 | 现在 |
|---|---|---|
| 点播放按钮没反应 | `togglePlay` 读 `isPlaying`，这值靠 play/pause **事件异步回写**，点快了就与真实状态相反，「想播放」变成「再 pause 一次」 | 改读 `player.paused`，不依赖响应式状态 |
| 换集后不起来 | 换源后 `$nextTick` 立刻 `play()`，那时 `readyState=0`，必被浏览器丢弃 | `_playWhenReady` 等 `canplay` 再播；记住播放意图，`AbortError` 后继续拉起 |
| 续播位置丢失、进度条 0:00 | `applyPosition` 只绑一次 `canplay`，那一瞬 `rs<3` 就 `return`，监听器已 auto-remove，位置永久丢失且**无任何日志** | `canplay` + `canplaythrough` + 定时兜底三重触发，带退避重试 |

另加一个**卡死看门狗**：点播放后 8 秒还没进 `readyState>=3` 或时间不走，
就 `load()` 中止卡住的拉取、重新加载并播放。实测首次请求被中断的场景下，
第 6 秒自愈、第 8 秒正常播放；修复前是永久卡死。

媒体错误也不再静默：会提示「第 N 集播放失败」，并说明可能是文件还在生成。
离开页面时先 `removeAttribute('src')` 再 `load()`，否则进行中的媒体拉取
不会被中止，连接与解码器一直被持有。

### 二点一、扫描导入的 PDF：作者变佚名、标题带文件名尾巴

**现象**：`秒懂速解小学数字画图 - 燕晓.pdf` 扫描导入后显示「作者：佚名」，
封面也没有。但同一文件直接调 `read_book_metadata` 能读出 `['燕晓']` 和 403KB 封面。

**根因**：`scan_service.py` 的扫描导入**自己写了一套** PDF 归一化，其中
`PDF_TILE_WITH_FILE_NAME=True` 分支**无条件**执行 `mi.authors = [_("佚名")]`。
`book.py` 的 `normalize_pdf_meta` 在 4.6.0-16 就修过同一个坑，但只覆盖网页上传
三条路径，扫描导入一直漏着。这是同类遗漏的第三处。

**修法**：

1. 扫描导入直接复用 `normalize_pdf_meta`，删掉自写的 15 行
2. **标题一律整串，不做拆分**。文件名前后可能带 `[作者]`/`[出版]`/`（版本）`，
   靠规则剥干净不现实，剥错比不剥更难发现。内嵌标题可信用内嵌，不可信才回退整串
3. 新增 `utils.guess_author_from_filename`：内嵌作者缺失时从文件名**保守**捞作者，
   只认「作者：X」「[X] 书名」「书名 (X)」「书名 - X」「by 多词西文名」五类信号，
   且候选要过人名形态校验（挡住出版社/版本/卷册/扩展名/英文标题词）。捞不到就佚名

   几个刻意做对的细节（33 条用例覆盖）：

   - **分隔符形态逐段取、不锚定结尾**。`三体 - 刘慈欣 - 重庆出版社` 这种三段式，
     只认最后一段会取到出版社再被否掉，白丢中间的真作者
   - **函数自己再剥一次扩展名**。调用方本来已剥，万一漏了 `- 燕晓.pdf` 会把扩展名
     一起吞进候选，再被 `pdf` 噪声词否掉
   - **`作者：张三 三体` 在空白处截断**，不贪婪吃到 20 字，避免把书名粘进人名
   - **含空格的候选按形态分流**：`上半部 下半部` 整段拒，`John Smith` 放行
   - **按「最靠右」择优**：书源习惯是书名在前作者在后；同位置按
     标签 > 括号 > 分隔符 > by 排序，结果可复现

**关于「PDF 标题使用文件名」开关**：打开时标题=文件名整串（可能带「- 作者」），
这是**预期行为**。想要干净标题就关掉该开关，内嵌标题可信时自动采用。

## 四点五、音频转码：现在会告诉你「源码率是多少」

原实现只报「有 N 个 mp3」，选档位全靠猜。这有个实际危害：源文件本来只有
32 kbps 时，选 128k 转出来只是把低质量放大，**文件更大、音质一点没提升**。

`-r1` 起扫描时会用 `ffprobe` 读一遍（基础镜像里 ffmpeg 自带，无需额外装），
页面显示：

```
现有音频
3 个 mp3 · 86.4 MB · 平均 48 kbps · 44.1 kHz · 总时长 6 小时 0 分
码率不均：最低 32 kbps，最高 64 kbps
⚠ 所选码率（64k）高于源文件平均码率（48 kbps）：转码后体积会变大，
   但音质不会提升。建议选择不高于源码率的档位，或直接不转。

01.mp3                                   64kbps · 28.8 MB
02.mp3                                   48kbps · 28.8 MB
03.mp3                                   32kbps · 28.8 MB
```

实现要点：

- `probe_mp3()` 任何异常都返回 `None`，**探测失败绝不影响扫描本身**
- 单本超过 200 个文件时抽样探测，避免大书卡住
- 「扫描全库」只探首曲 + 统计体积（全库上千文件做全量 ffprobe 会把秒级变分钟级）

## 四点六、严重 bug：转码此前从来没成功过

`-r2` 修。原代码：

```python
tmp = dst + ".tmp"      # → xxx.m4a.tmp
```

ffmpeg **只看最后一个后缀**认容器格式，`.tmp` 它不认识，直接报：

```
Error initializing the muxer for xxx.m4a.tmp: Invalid argument
Error opening output files: Invalid argument
```

于是每个文件都失败。因为失败路径会保留 mp3、删除半成品，**数据不会丢，
但一个 m4a 也生成不出来**——功能等于不可用。

修法：临时文件改成 `xxx.tmp.m4a`（后缀仍是 `.m4a`），再加 `-f mp4` 双保险。

### 顺手修老记录（可选）

`audiodir:` 标记记录在「已导入」列表里原来书名空白，看着像失败。新版会带书名，
但**老记录不会自动改**。想立刻改观可以跑：

```sh
docker exec audiobook-mybooks-1 sh -c 'gosu mybooks python3 -c "
import sqlite3, os
db = sqlite3.connect(\"/data/books/calibre-webserver.db\")
rows = list(db.execute(\"select id, path from scanfiles where hash like \x27audiodir:%\x27 and (title is null or title=\x27\x27)\"))
for i, p in rows:
    db.execute(\"update scanfiles set title=? where id=?\", (os.path.basename(os.path.normpath(p))[:100], i))
db.commit()
print(\"已修\", len(rows), \"条\")
"'
```

这些标记是「本目录音频已随书带走」的防重记录，**不是书籍**，删掉会导致

## 七、怎么在 NAS 上跑测试

先说结论：**能跑，但不能直接敲 `pytest tests/...`**，原因有两个：

1. **生产镜像里没有 pytest**。`Dockerfile` 里 `pip install flake8 pytest` 只出现在
   `FROM ... AS test` 那个阶段；生产阶段是另一个 `FROM ... AS production`，
   装的是 `requirements_release.txt`，里面没有 pytest。
2. **生产镜像里没有 `tests/` 目录**。生产阶段只 `COPY webserver/ docker/ tools/`，
   `tests/` 是 test 阶段才拷进去的。

所以 `docker exec audiobook-mybooks-1 pytest tests/test_meta_merge.py` 必然报
`pytest: not found` 或 `file or directory not found`。

### 用脚本跑（推荐）

把 `跑测试.sh` 和部署包放同一目录，然后：

```bash
cd /volume1/docker
sh 跑测试.sh
```

脚本会：从部署包里解出两份测试 → 检查容器里有没有 pytest（没有就临时装，
装不上自动退回 `unittest`，结果等价）→ 拷进容器 `/tmp/mbtests` 跑 → 跑完删掉。

预期输出末尾是 `OK`，共 **69 + 20 = 89 例**。

### 手工跑

```bash
# 1. 把测试文件塞进容器
docker cp audiobook/tests/test_meta_merge.py    audiobook-mybooks-1:/tmp/t/
docker cp audiobook/tests/test_audio_narrator.py audiobook-mybooks-1:/tmp/t/

# 2. 没有 pytest 就装一个（只影响当前容器，重启即失效）
docker exec audiobook-mybooks-1 sh -c \
  'pip install -q pytest -i https://mirrors.aliyun.com/pypi/simple/ --break-system-packages'

# 3. 跑
docker exec audiobook-mybooks-1 sh -c \
  'cd /var/www/mybooks && PYTHONPATH=/var/www/mybooks gosu mybooks python3 -m pytest /tmp/t -q'

# 4. 清理
docker exec audiobook-mybooks-1 sh -c 'rm -rf /tmp/t'
```

`PYTHONPATH=/var/www/mybooks` 不能省，否则 `import webserver` 会失败。

### 这两份测试测什么

| 文件 | 例数 | 覆盖 |
|---|---|---|
| `test_meta_merge.py` | 69 | PDF 标题/作者归一化、文件名作者推断（33 例）、重新导入并入既有书时的元数据合并 |
| `test_audio_narrator.py` | 20 | 演播者提取、写 `#narrator`/tags/comments、导入不把 artist 当作者、扫书带音频时补演播者 |

全部用 `unittest.mock`，**不碰数据库、不联网**，所以对现有书库没有影响。
