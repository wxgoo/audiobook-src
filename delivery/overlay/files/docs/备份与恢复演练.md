# 备份与恢复演练（P0）

> 对应脚本：[`scripts/backup.sh`](../scripts/backup.sh)、[`scripts/backup_run.py`](../scripts/backup_run.py)
> 适用版本：4.6.0-build.24 及之后的部署
> 本文所有默认值均为「已代选，可调整」；括号里的「待确认」项表示仍建议结合自己的数据量复核。

---

## 1. 一句话

`scripts/backup.sh` 每次运行都会产出一份**可直接整体恢复的书库快照**：
数据库用 SQLite 在线备份 API 拿一致副本，书/音频用硬链接快照（未变化文件与上一份共享磁盘块），
默认每天 03:30 跑一次、保留 7 天 + 4 周 + 6 个月。恢复流程见第 7 节，恢复演练见第 8 节。

**它解决的是原方案里的 F1：升级脚本只备份 `*.db`，不备份书和音频。**

---

## 2. 备份范围

| 备份 | 不备份 |
|---|---|
| `/data/books/library/`（电子书、封面、每本书的 `.audio/` 音频） | `/data/cache/`（可再生，默认排除） |
| `/data/books/imports/audiobooks/`（待导入音频） | `/data/log/`（默认排除，`EXCLUDE_DIRS=cache` 可改为包含） |
| `/data/books/calibre-webserver.db`（站点库：用户、设置、进度） | `/data/.backup-tmp/`（脚本临时目录，默认排除） |
| `/data/books/library/metadata.db`（calibre 元数据库） | 源码目录 `/volume1/docker/audiobook/`（可由部署包/git 重建） |
| `/data/reader/`、`/data/sync/`、`/data/.permission` | Docker 镜像本身（`sh scripts/deploy.sh` 走 BuildKit 可重建，不要再用 legacy builder） |

数据库除了进文件快照，还会单独走一遍**在线备份**，落到 `db/<时间戳>/`：
文件快照里的 DB 是「某一瞬间的磁盘状态」，而在线备份是 SQLite 保证一致性的副本；
恢复数据库时**优先用 `db/<时间戳>/` 里的那份**。

## 3. 备份目录布局

```text
/volume1/docker/audiobook-backup/          # BACKUP_ROOT，与数据目录分离
├── db/
│   └── 20261107-033000/
│       ├── calibre-metadata.db            # metadata.db 的一致副本
│       ├── webserver.db                   # calibre-webserver.db 的一致副本
│       └── manifest.json                  # sha256 / integrity_check / 书数
├── files/
│   ├── 20261107-033000/                   # 完整目录树（硬链接快照）
│   └── 20261108-033000/                   # 与上一份共享未变化文件的 inode
├── manifests/
│   └── backup-20261107-033000.json        # 本次运行的完整清单
├── .backup.lock/                          # 单实例锁（运行中才存在）
└── backup.log                             # 由 cron 重定向产生（可选）
```

`files/<时间戳>/` 与 `/data` 的目录结构一一对应，所以恢复单本书 =
`cp -a /volume1/docker/audiobook-backup/files/<ts>/books/library/<作者>/<书名> (id)/ /volume1/docker/audiobook-data/books/library/<作者>/`。

## 4. 参数（全部可调）

### 4.1 命令行选项

| 选项 | 作用 |
|---|---|
| 无参数 | 全量一次：数据库 + 文件快照 + 按策略清理旧快照 |
| `--db-only` | 只备份数据库（秒级，适合每小时跑） |
| `--files-only` | 只备份书库/音频（不碰数据库） |
| `--dry-run` | 只打印计划，不写任何文件 |
| `--no-prune` | 本次不清理旧快照（手工保留某个现场时用） |
| `--list` | 列出已有快照及各自占用空间 |
| `-h, --help` | 帮助 |

### 4.2 环境变量

| 变量 | 默认值 | 说明 | 是否可调 |
|---|---|---|---|
| `DATA_DIR` | `/volume1/docker/audiobook-data` | 数据目录，必须与 compose 的挂载一致 | 可调（换机必改） |
| `BACKUP_ROOT` | `/volume1/docker/audiobook-backup` | 备份根目录，**不能位于 `DATA_DIR` 内** | 可调 |
| `APP_CONTAINER` | `audiobook-mybooks-1` | 用于判断站点是否在运行 | 可调 |
| `BACKUP_IMAGE` | `mybooks-local:latest` | 备份用的 Python 运行环境（现有镜像即可） | 可调 |
| `RUNNER` | `auto` | `auto`/`docker`/`local`；auto 优先用镜像，其次本机 python3 | 可调 |
| `DOCKER_USER` | `0:0` | 备份容器内运行身份；备份盘属主非 root 时可设 `1026:100` | 可调 |
| `KEEP_DAILY` | `7` | 最近 7 天每天保留最新一份 | 可调 |
| `KEEP_WEEKLY` | `4` | 最近 4 周每周保留一份 | 可调 |
| `KEEP_MONTHLY` | `6` | 最近 6 个月每月保留一份（**跨月/跨周快照的唯一长期副本**） | 可调 |
| `EXCLUDE_DIRS` | `cache,log,.backup-tmp` | 任意层级出现这些目录名即跳过 | 可调 |
| `EXCLUDE_PATTERNS` | `*.tmp,*.part,*.partial,*.swp` | 跳过未完成的临时文件，避免备份到半截音频 | 可调 |
| `MIN_FREE_GB` | `5` | 备份盘剩余低于此值直接中止，防止撑爆磁盘 | 可调 |
| `LOCK_WAIT` | `0` | 已有备份在跑时最多等待秒数；0 = 立即跳过 | 可调 |
| `TZ` | `Asia/Shanghai` | 备份容器时区（影响时间戳） | 可调 |

> 首次运行前把 `DATA_DIR` / `BACKUP_ROOT` 改成自己的实际路径；其余默认值可直接用。

## 5. 使用方式

### 5.1 首次备份（手工验证一遍）

```sh
# 在 NAS 上以 root（或能读写备份目录的用户）执行
cd /volume1/docker/audiobook
sh scripts/backup.sh --dry-run       # 先看参数对不对
sh scripts/backup.sh                 # 正式跑一次
sh scripts/backup.sh --list          # 看快照与占用
```

预期输出：数据库两条「已备份」、文件快照「复制 N 个 / 硬链接复用 M 个」、
最后 `备份完成，状态=ok`。退出码 `0`。

### 5.2 日常定时

群晖「控制面板 → 任务计划 → 新增 → 计划的任务 → 用户定义的脚本」：

```sh
/bin/sh /volume1/docker/audiobook/scripts/backup.sh \
  >> /volume1/docker/audiobook-backup/backup.log 2>&1
```

- 账户：`root`（需要读写 `DATA_DIR` 与 `BACKUP_ROOT`）
- 频率：每天一次，建议 03:30（低峰）
- 若要更低 RPO：再加一条 `backup.sh --db-only`，每小时一次（DB 小，秒级完成）

Linux/NAS 通用 crontab：

```cron
30 3 * * *  /bin/sh /volume1/docker/audiobook/scripts/backup.sh >> /volume1/docker/audiobook-backup/backup.log 2>&1
0 * * * *   /bin/sh /volume1/docker/audiobook/scripts/backup.sh --db-only >> /volume1/docker/audiobook-backup/backup.log 2>&1
```

> 同一条命令不会并发跑：`backup.sh` 用 `.backup.lock` 做单实例锁，后到的直接跳过（退出码 4）。

### 5.3 关键操作前临时备份

```sh
# 升级前（比 upgrade.sh 的 DB-only 备份更完整）
sh scripts/backup.sh

# 批量去重 / 大改目录结构前，只要数据库
sh scripts/backup.sh --db-only
```

## 6. 全量 / 增量说明与空间估算

- **逻辑全量**：每份 `files/<ts>/` 都是完整目录树，单独拿出来就能整体恢复，不依赖其他快照。
- **物理增量**：与上一份相比，只有大小+mtime 变化的文件会被真正复制，其余文件硬链接到上一份的 inode。
  所以新增占用 ≈ 本次变动文件的大小，而不是整库大小。
- **首份最贵**：第一份等于整库数据量；之后每天新增通常是几十 MB（新书 + 转码音频 + DB）。
- 粗估（已代选，可按实际规模复核）：

| 书库规模 | 首份占用 | 每日增量（估） | 21 份快照总占用（估） |
|---|---|---|---|
| 10 万册、无音频 | 约库体积 ×1 | < 100MB | 库体积 ×1.1 以内 |
| 10 万册 + 2TB 音频 | 约 2TB | 100MB ~ 2GB（看新增/转码量） | 2TB + 每日增量累计 |

> 前提：`BACKUP_ROOT` 与数据在**支持硬链接的文件系统**上（Btrfs / ext4 / NTFS）。
> exFAT、FAT32 不支持硬链接，脚本会自动退化为全量复制并打印告警——
> 此时 21 份快照就是 21 倍占用，务必调小保留份数或换盘。

## 7. 校验与监控

每次运行都会写 `manifests/backup-<ts>.json`，含：

- 两个数据库的 `sha256`、`integrity_check` 结果、`books` 行数；
- 文件快照的文件数/目录数/复制数/硬链接数/错误列表；
- 被清理的旧快照列表。

手工核对：

```sh
# 最近一次清单
ls -t /volume1/docker/audiobook-backup/manifests | head -1 | \
  xargs -I{} cat /volume1/docker/audiobook-backup/manifests/{}
```

`integrity` 不是 `ok`、或 `status` 为 `ok-with-warnings` 时，先看日志里的 `!!` 行再决定是否信任该备份。

退出码约定（cron 可据此告警）：

| 退出码 | 含义 | 处理 |
|---|---|---|
| 0 | 成功 | — |
| 2 | 完成但有告警（个别文件失败 / DB 校验异常） | 看日志 `!!` 行 |
| 3 | 失败/中止（数据目录不存在、空间不足、快照不完整） | 立即排查；**上一份快照仍可用** |
| 4 | 被跳过（另一实例在运行/锁不可用） | 单次无害；**连续多日 4 = 锁或调度异常**，立即排查 |

> cron 告警条件建议 `RC != 0`：2 是「备份可用但有隐患」，4 是「今天根本没备」——
> 只盯 `>=3` 会把连续跳过当成正常（build.20 复审结论）。

## 8. 恢复演练

> 恢复演练的黄金法则：**先演练、再依赖**。建议每季度做一次，演练目标目录不要用生产目录。

### 8.1 演练准备

```sh
TS=20261107-033000                       # 选一份快照
BK=/volume1/docker/audiobook-backup
DRILL=/volume1/docker/audiobook-restore-drill
rm -rf "$DRILL"; mkdir -p "$DRILL"
```

### 8.2 场景一：恢复单本书（最常见）

```sh
# 书目录形如 library/<作者>/<书名> (id)/
rsync -aHAX "$BK/files/$TS/books/library/<作者>/<书名> (id)/" \
           "/volume1/docker/audiobook-data/books/library/<作者>/"
# 若该书在 calibre 里已丢失，重启后在「扫描」里重新导入该书目录即可
```

单文件恢复不需要停站点；恢复后在后台「扫描 → 导入」补登记。

### 8.3 场景二：只恢复数据库（误删用户/设置错乱/进度丢失）

```sh
# 1. 停站点（必须，避免写入覆盖）
cd /volume1/docker/audiobook && docker compose down

# 2. 覆盖数据库，并清掉旧的 WAL/SHM
cp "$BK/db/$TS/calibre-metadata.db" /volume1/docker/audiobook-data/books/library/metadata.db
cp "$BK/db/$TS/webserver.db"        /volume1/docker/audiobook-data/books/calibre-webserver.db
rm -f /volume1/docker/audiobook-data/books/library/metadata.db-wal \
      /volume1/docker/audiobook-data/books/library/metadata.db-shm \
      /volume1/docker/audiobook-data/books/calibre-webserver.db-wal \
      /volume1/docker/audiobook-data/books/calibre-webserver.db-shm

# 3. 起站点
docker compose up -d
```

数据库与书库不一致时（例如用旧 DB 配新书文件），以「书文件为准 + 后台重新扫描」最稳。

### 8.4 场景三：整库恢复到本机（同机灾难恢复）

```sh
cd /volume1/docker/audiobook && docker compose down

# 保留现场，别直接覆盖
mv /volume1/docker/audiobook-data /volume1/docker/audiobook-data.bad-$(date +%Y%m%d)

# 新建空目录，从快照整体拷回（空目录无需 --delete）
mkdir -p /volume1/docker/audiobook-data
rsync -aHAX "$BK/files/$TS/" /volume1/docker/audiobook-data/

# 用一致性的数据库副本替换快照里的磁盘态 DB
cp "$BK/db/$TS/calibre-metadata.db" /volume1/docker/audiobook-data/books/library/metadata.db
cp "$BK/db/$TS/webserver.db"        /volume1/docker/audiobook-data/books/calibre-webserver.db

# 让容器首启重新校正属主（快照内的 .permission 可能仍是旧 UID）
rm -f /volume1/docker/audiobook-data/.permission

docker compose up -d
```

> 不要对生产目录直接 `rsync --delete`：快照里排除了 `cache/`、`log/`，
> `--delete` 会顺手删掉当前日志和缓存。用「空目录 + 整体拷回」最安全。

### 8.5 场景四：换机 / 换 NAS（灾难恢复）

1. 新机装 Docker、创建 `/volume1/docker`。
2. 把 `audiobook-backup` 整个目录拷到新机（移动硬盘 / 网络共享均可）。
3. 按 `scripts/deploy.sh` 部署同版本源码并构建镜像（不带数据）。
4. 按 8.4 把 `files/<最新 ts>/` 恢复到新的 `audiobook-data`，再覆盖数据库。
5. 按 `docs/VMM迁移手册.md` 校对 `docker-compose.yml` 的 `PUID` / `PGID` / 端口后再启动。

### 8.6 恢复后验收清单

```sh
C=audiobook-mybooks-1

# 书数
docker exec "$C" python3 - <<'PY'
import sqlite3
db = sqlite3.connect('/data/books/library/metadata.db')
print('books:', db.execute('select count(*) from books').fetchone()[0])
PY

# 数据库完整性
docker exec "$C" python3 - <<'PY'
import sqlite3
for p in ('/data/books/library/metadata.db', '/data/books/calibre-webserver.db'):
    print(p, sqlite3.connect(p).execute('pragma integrity_check').fetchone()[0])
PY

# 音频数量（应与恢复前一致）
find /volume1/docker/audiobook-data/books -path '*/.audio/*' -type f | wc -l

# 进程与页面
docker exec "$C" supervisorctl status
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:9800/
```

再人工确认：登录、书架列表、随机点开 3 本书、播放 1 个有声书（拖动进度条验证 Range）、阅读器打开 1 本书。

### 8.7 演练记录模板

| 日期 | 快照 | 场景 | 耗时 | 书数 | 音频数 | 页面 | 播放 | 结论 |
|---|---|---|---|---|---|---|---|---|
| 2026-11-07 | 20261107-033000 | 场景三 | 42min | 待填 | 待填 | 200 | 正常 | 通过 |

## 9. RPO / RTO 默认值（已代选，可调整）

| 指标 | 默认值 | 达成方式 | 说明 |
|---|---|---|---|
| RPO（最多丢多少数据） | **24 小时** | 每天 03:30 全量快照 | 加一条每小时 `--db-only` 可把「设置/进度/用户」的 RPO 降到 1 小时；书/音频仍为 24 小时 |
| RTO（多久恢复服务） | **≤ 4 小时**（≤1TB，同机同盘） | 场景三/四流程 | 主要是 rsync 回拷时间（按 100MB/s 估）；换机另算拷贝介质时间 |
| 快照保留 | 7 天 + 4 周 + 6 个月 | `KEEP_DAILY/WEEKLY/MONTHLY` | 跨月快照是长期唯一副本，至少保留 6 个月 |
| 备份窗口 | 03:30 起，预计 < 30 分钟 | cron | 首份或大改后可能更久 |

> 这些值是按「单机 NAS、10 万册量级」保守取的默认值；实际规模、可接受 RPO/RTO
> 如与上表不同，只改环境变量即可，不用改脚本。

## 10. 局限与注意事项

1. **硬链接依赖文件系统**：`BACKUP_ROOT` 与数据建议在同一 NAS 卷；换外接盘时确认是
   Btrfs/ext4/NTFS。exFAT/FAT32 上脚本会打印「不支持硬链接」告警，占用会膨胀。
2. **备份不是异地副本**：同一块盘/同一台 NAS 上的快照挡不住整机损坏、勒索软件。
   建议再用 Hyper Backup / restic 把 `audiobook-backup` 同步到异地（脚本不负责这一层）。
3. **快照内的 DB 不作为首选**：恢复数据库一律用 `db/<ts>/` 下的在线副本。
4. **文件属主**：备份容器默认以 root 运行，备份文件属主为 root；恢复后删除
   `/data/.permission` 让容器首启重新 `chown`，或手工 `chown -R 1026:100`。
5. **备份期间写入**：文件快照不保证「同一时刻」的全局一致（硬链接快照逐文件同步），
   所以恢复后建议在后台跑一次「扫描」对齐 calibre 与磁盘状态。
6. **已完成上传但还在合并的临时文件**：默认由 `EXCLUDE_PATTERNS` 跳过，避免备份到半截文件。
7. **不要**把 `BACKUP_ROOT` 放在 `DATA_DIR` 里面（脚本会直接拒绝）。

## 11. 回滚（本项可安全撤销）

本项只**新增**文件，不改任何运行时 Python/前端代码，因此回滚就是撤销提交：

```sh
git revert <本项提交的 sha>     # 或在部署目录直接删除下面两个文件
rm -f scripts/backup.sh scripts/backup_run.py docs/备份与恢复演练.md
rm -rf /volume1/docker/audiobook-backup     # 备份数据按需保留
```

已产出的快照不受影响，删掉脚本也能手工按第 8 节恢复。

## 12. 本项已代选的决定

| 决定 | 取值 | 理由 | 可调方式 |
|---|---|---|---|
| 备份实现方式 | Python 标准库 + 现有镜像 | NAS 不一定有 rsync/sqlite3 命令行，Python 一定在镜像里 | `RUNNER=local` 或自行换 rsync |
| 数据库一致性 | SQLite 在线备份 API | 站点不停止也能拿到一致副本，避免停服窗口 | 无需调 |
| 文件增量 | 硬链接快照（逻辑全量） | 每份都能单独恢复，增量只占新增空间 | 换盘/换保留策略即可 |
| 默认周期 | 每天 03:30 一次 | 低峰、RPO 24h 保守 | cron 改成任意时间 |
| 默认保留 | 7/4/6（日/周/月） | 覆盖近一周回滚 + 半年审计 | `KEEP_*` |
| RPO / RTO | 24h / ≤4h | 保守默认，待按实际规模复核 | 见第 9 节 |
| 排除项 | `cache`、`log`、临时文件 | 可再生 / 体积大 / 半截文件 | `EXCLUDE_DIRS`、`EXCLUDE_PATTERNS` |
| 运行身份 | 容器内 root | 保证能读全库、写备份盘 | `DOCKER_USER=1026:100` |

# 附：NAS 备份演练清单（Step-by-Step）

> **本文只作说明，不要从文档复制命令执行**（缩进、换行、引号、全角字符在 DSM 上会导致失败）。
> 实际操作用可执行脚本：`delivery/nas/`（入口见 `delivery/nas/README-NAS.md`）。
> 下文命令仅用于理解步骤，等价操作以脚本参数为准。

目标：在 NAS 上**不碰真实书库改动**的前提下，完整跑一次「全量 → 增量 → 校验 → 清理」，
确认 `scripts/backup.sh` 可用，并把结果留下作为上线前证据。

> 演练使用**独立的备份目录**（`audiobook-backup-drill`），成功后再切到正式目录。
> 原始部署包不要动；本清单只读数据目录，只写演练备份目录。

## 0. 准备：路径与环境变量

先 SSH 登录 NAS，进入源码目录（按实际位置替换）：

```sh
export SRC_DIR=/volume1/docker/audiobook-src-opt      # 源码仓库（含 scripts/backup.sh）
export DATA_DIR=/volume1/docker/audiobook-data        # 站点数据目录（真实数据）
export DRILL_ROOT=/volume1/docker/audiobook-backup-drill   # 演练备份目录（独立）
export APP_CONTAINER=audiobook-mybooks-1              # 正在运行的应用容器名
cd "$SRC_DIR"
```

逐条确认（每条都要有输出，否则先解决）：

```sh
ls -ld "$DATA_DIR"                    # 目录存在
ls -l "$DATA_DIR/books/library/metadata.db"      # calibre 元数据库存在
ls -l "$DATA_DIR/books/calibre-webserver.db"     # 站点数据库存在
df -h "$(dirname "$DRILL_ROOT")"      # 剩余空间 ≥ 数据目录 × 1.2
docker inspect -f '{{.State.Running}}' "$APP_CONTAINER"   # 期望 true
```

创建演练目录（必须位于数据目录之外，脚本会拒绝备份目录落在数据目录内部）：

```sh
mkdir -p "$DRILL_ROOT"
```

> 可调参数（都有默认值，演练先用默认）：
> `KEEP_DAILY=7`、`KEEP_WEEKLY=4`、`KEEP_MONTHLY=6`、`MIN_FREE_GB=5`、
> `EXCLUDE_DIRS=cache,log,.backup-tmp`、`EXCLUDE_PATTERNS=*.tmp,*.part,*.partial,*.swp`。

## 1. 预检：帮助与 dry-run（不写任何文件）

```sh
RUNNER=local sh scripts/backup.sh --help
RUNNER=local DATA_DIR="$DATA_DIR" BACKUP_ROOT="$DRILL_ROOT" sh scripts/backup.sh --dry-run
```

预期输出（摘录）：

```
 audiobook 数据备份  ...
   数据目录 : /volume1/docker/audiobook-data（站点运行中，数据库走在线备份）
   备份目录 : /volume1/docker/audiobook-backup-drill
   模式     : all   清理旧快照: 1   dry-run: 1
   保留策略 : 日 7 / 周 4 / 月 6
   运行器   : local (python3)
...
[backup] [dry-run] 数据目录: ...
[backup] [dry-run] 备份目录: ...
[backup] [dry-run] 时间戳: ...，模式: all
```

判定：无 `!!` 行、退出码 0。若提示 `本机没有 python3` → 改用第 6 节 docker 路径。

## 2. 第一步：只备份数据库（秒级）

```sh
RUNNER=local DATA_DIR="$DATA_DIR" BACKUP_ROOT="$DRILL_ROOT" \
  sh scripts/backup.sh --db-only
echo "exit=$?"
```

预期输出（关键行）：

```
   数据目录 : ...（站点运行中，数据库走在线备份）
[backup] 数据库已备份: <DATA_DIR>/books/calibre-webserver.db -> <DRILL_ROOT>/db/<ts>/webserver.db（x.x MB，sqlite-backup-api）
[backup] 数据库已备份: <DATA_DIR>/books/library/metadata.db -> <DRILL_ROOT>/db/<ts>/calibre-metadata.db（x.x MB，sqlite-backup-api）
[backup] 备份完成，状态=ok，清单=<DRILL_ROOT>/manifests/backup-<ts>.json
 备份成功。恢复步骤见 docs/备份与恢复演练.md
exit=0
```

检查点（全部满足才算通过）：

```sh
TS=$(ls -1 "$DRILL_ROOT/db" | sort | tail -1); echo "$TS"
ls -l "$DRILL_ROOT/db/$TS"/            # webserver.db、calibre-metadata.db、manifest.json
python3 - <<'PY'
import json, os, sqlite3, glob
root = os.environ["DRILL_ROOT"]
ts = sorted(os.listdir(os.path.join(root, "db")))[-1]
for name in ("webserver.db", "calibre-metadata.db"):
    p = os.path.join(root, "db", ts, name)
    con = sqlite3.connect(p)
    print(name, con.execute("PRAGMA integrity_check").fetchone()[0],
          "tables=", con.execute("SELECT count(*) FROM sqlite_master WHERE type='table'").fetchone()[0])
    con.close()
m = json.load(open(os.path.join(root, "manifests", "backup-%s.json" % ts)))
print("manifest:", m["status"], len(m.get("databases", [])))
PY
```

期望：两个库都打印 `ok`；`manifest: ok 2`。

## 3. 第二步：第一次全量（数据库 + 文件）

```sh
RUNNER=local DATA_DIR="$DATA_DIR" BACKUP_ROOT="$DRILL_ROOT" \
  KEEP_DAILY=7 KEEP_WEEKLY=4 KEEP_MONTHLY=6 MIN_FREE_GB=5 \
  sh scripts/backup.sh
echo "exit=$?"
```

预期输出（关键行）：

```
[backup] 数据库已备份: ...（sqlite-backup-api）
[backup] 文件快照完成：N 个文件、M 个目录，复制 N 个（x.x GB），硬链接复用 0 个，耗时 xx.xs
[backup] 备份完成，状态=ok，清单=<DRILL_ROOT>/manifests/backup-<ts>.json
 备份成功。恢复步骤见 docs/备份与恢复演练.md
exit=0
```

判定：`硬链接复用 0 个`（首份没有可复用文件）；无 `!!` 行；`files/<ts>/books/library/metadata.db` 存在。

记录体积：

```sh
TS=$(ls -1 "$DRILL_ROOT/files" | sort | tail -1)
du -sh "$DRILL_ROOT/files/$TS"
find "$DRILL_ROOT/files/$TS" -type f | wc -l
```

## 4. 第三步：第二次全量（验证增量）

至少间隔 60 秒再跑（时间戳精确到秒，避免目录同名）：

```sh
sleep 60
RUNNER=local DATA_DIR="$DATA_DIR" BACKUP_ROOT="$DRILL_ROOT" sh scripts/backup.sh
echo "exit=$?"
```

预期：第二份的 `硬链接复用` 数量 **接近文件总数**（未变化文件共享 inode），
`复制` 数量与字节数应很小。检查：

```sh
TS2=$(ls -1 "$DRILL_ROOT/files" | sort | tail -1)
du -sh "$DRILL_ROOT/files/$TS2"                         # 应明显小于第一份
stat -c '%i %n' "$DRILL_ROOT/files/$TS2/books/library/metadata.db" \
              "$DRILL_ROOT/files/$TS"/books/library/metadata.db 2>/dev/null
# 两次输出的 inode 相同 = 硬链接复用成功
```

若提示 `!! 备份目录不支持硬链接`：说明备份盘是 exFAT/FAT 或无硬链接权限，
仍可恢复但空间会翻倍，需改用支持硬链接的文件系统（ext4/Btrfs/XFS）。

## 5. 第四步：校验与保留策略

```sh
RUNNER=local DATA_DIR="$DATA_DIR" BACKUP_ROOT="$DRILL_ROOT" sh scripts/backup.sh --list
python3 - <<'PY'
import json, glob, os
root = os.environ["DRILL_ROOT"]
for p in sorted(glob.glob(os.path.join(root, "manifests", "*.json")):
    m = json.load(open(p))
    print(os.path.basename(p), m["status"], m.get("files", {}).get("copied"))
PY
```

期望：两份 manifest 都为 `ok`（或 `ok-with-warnings`，并确认告警只是被忽略的临时文件）。

演练成功判定（5 项全过）：

1. 三次执行退出码均为 `0`；
2. 两份 manifest 存在且 `status=ok`；
3. 两个数据库副本 `PRAGMA integrity_check = ok`；
4. 第二份快照 `硬链接复用 > 0` 且体积明显小于第一份；
5. `--list` 能看到 `db/`、`files/`、`manifests/` 三个目录。

## 6. docker 路径（Windows 上未验证，必须在 NAS 上单独跑一次）

前置：NAS 上已构建应用镜像（`docker image ls mybooks-local:latest` 有输出）。
若没有：在 compose 目录执行 `docker compose build`（或 `docker build -t mybooks-local:latest .`）。

```sh
RUNNER=docker BACKUP_IMAGE=mybooks-local:latest DOCKER_USER=0:0 \
  DATA_DIR="$DATA_DIR" BACKUP_ROOT="$DRILL_ROOT" \
  sh scripts/backup.sh --dry-run

RUNNER=docker BACKUP_IMAGE=mybooks-local:latest DOCKER_USER=0:0 \
  DATA_DIR="$DATA_DIR" BACKUP_ROOT="$DRILL_ROOT" \
  sh scripts/backup.sh --db-only
```

脚本内部实际执行（可复制出来单独排障）：

```sh
docker run --rm -i --network none --user 0:0 -e TZ=Asia/Shanghai \
  -v "$DATA_DIR:/data" -v "$DRILL_ROOT:/backup" \
  --entrypoint python3 mybooks-local:latest - \
  --data /data --backup /backup --mode db --keep-daily 7 --keep-weekly 4 --keep-monthly 6 \
  < scripts/backup_run.py
```

docker 路径检查点：

- `docker image inspect mybooks-local:latest` 成功，否则脚本退出 3 并提示构建；
- 容器内以 `--user 0:0` 运行，写 `/backup` 时不应出现 `Permission denied`；
- `--network none` 下仍能完成（备份不需要网络）；
- 容器一次性退出，`docker ps -a` 不应留下名字含 `mybooks` 的临时容器。

常见失败：

| 现象 | 原因 | 处理 |
|---|---|---|
| `找不到镜像 mybooks-local:latest` | 镜像名与 compose 不一致 | `docker images` 查实际 tag，用 `BACKUP_IMAGE=` 覆盖 |
| `Permission denied` 写 `/backup` | 目录属主/权限 | `DOCKER_USER=0:0`；或 `chown` 备份目录 |
| 数据目录为空 | 挂载路径写错 | 用绝对路径，`ls -ld` 先确认 |
| 退出码 3 且提示「备份目录不能位于数据目录内部」 | 路径包含关系 | 换到独立目录 |

> **重要**：docker 路径当前只在代码层验证过，尚未在 Windows 或 NAS 实机跑通；
> 首次务必用 `--db-only` 小步验证，再跑全量。

## 7. 失败排查（local / docker 通用）

| 退出码 / 输出 | 含义 | 处理 |
|---|---|---|
| `2` + `已有备份进程在运行（pid …）` | 上一轮未结束 | 等它结束；确认无进程后删 `$BACKUP_ROOT/.backup.lock` |
| `2` + `备份完成但有告警` | 部分文件被跳过 | 看 `!!` 行；临时文件可忽略，权限错误需修 |
| `3` + `备份盘剩余空间不足` | 低于 `MIN_FREE_GB` | 扩容或调小 `MIN_FREE_GB` |
| `3` + `在线备份失败（容器可能在写入）` | 容器未停且不能冷拷贝 | 保持容器运行（走在线备份）；或停容器后 `--db-only` 会冷拷贝 |
| `3` + `完整性校验失败` | 副本损坏 | 检查源库磁盘健康；重跑一次；仍失败则停容器冷拷贝 |
| `3` + `文件快照失败，已清理不完整快照` | 读取中断/权限 | 看日志错误；修权限后重跑 |
| `!! 有 N 个文件未能备份` | 个别文件读失败 | 输出前 10 条；确认是否可忽略 |

## 8. 演练收尾

1. 保留 `$DRILL_ROOT/manifests/*.json` 与执行日志作为证据。
2. 演练目录可保留数日再删；删除前确认 `BACKUP_ROOT` 不是正式目录：

```sh
echo "$DRILL_ROOT"     # 必须是 audiobook-backup-drill
# 确认无误后：rm -rf "$DRILL_ROOT"
```

3. 正式启用：把 cron 指向正式目录（默认值可覆盖）：

```sh
# 每天 03:30，日志追加
30 3 * * * /bin/sh $SRC_DIR/scripts/backup.sh \
  >> /volume1/docker/audiobook-backup/backup.log 2>&1
```
